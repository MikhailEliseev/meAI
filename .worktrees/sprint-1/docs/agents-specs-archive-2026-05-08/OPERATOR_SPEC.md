# OPERATOR - Спецификация требований

**Дата:** 2026-05-08  
**Статус:** Требования от владельца агентства

---

## 🎯 РОЛЬ И НАЗНАЧЕНИЕ

**Operator = Project Manager агентства**

### Основная роль:
- **Связь между клиентами/проектами и агентами-исполнителями**
- **Оперативное управление агентством**
- **Project management для всех клиентских проектов**

### Ключевые обязанности:

1. **Управление клиентами и проектами:**
   - Создавать папки клиентов
   - Создавать папки проектов для каждого клиента
   - Вести базу всех клиентов
   - Один клиент → несколько проектов (иерархия: Клиент → Проект → Агенты)

2. **Сохранение контекста:**
   - Записи со встреч
   - Emails
   - Письма
   - Вся коммуникация с клиентом
   - **Цель:** Не потерять контекст проекта

3. **Стратегический контроль:**
   - Следить, чтобы проект не отклонялся от стратегии
   - Корректировать стратегию при новых вводных от клиента
   - Запускать новые инструменты по необходимости
   - Собирать отчётность для клиентов

4. **Информирование:**
   - Держать клиента в курсе проекта
   - Держать владельца агентства (тебя) в курсе всех проектов

## 📥 ВХОДНЫЕ ЗАДАЧИ ОТ ВЛАДЕЛЬЦА

### Типы задач:

1. **Отчётность:**
   - "Сформировать отчёт по текущей ситуации проекта X"
   - Следить за своевременностью отчётов
   - Обеспечить клиенту своевременную информацию

2. **Запуск направлений:**
   - "Запустить рекламную кампанию в Яндекс Директе по направлению Y"
   - "Клиент запускает новый аппарат/услугу → запусти всю цепочку"
   - Operator → запускает агентов → исследует рынок → разрабатывает стратегию → выполняет

3. **Мониторинг и корректировки:**
   - Отследить результат
   - Сделать корректировки
   - Дать рекомендации и выводы: что получилось, что не получилось
   - Сформировать следующий план

### Формат постановки задач:

**Способ:** Голосовые или текстовые сообщения через Telegram-бот

**Требование к прозрачности:**
Задачи должны быть видны на дашборде по проекту:
- Как мы двигаемся
- Какие задачи в работе
- Какие задачи в бэклоге
- Какая стратегия
- К чему идём
- Какие цели
- Текущий спринт (недельный)

**Видимость:**
- Для клиента (по его проектам)
- Для владельца агентства (по всем проектам)

## 🔄 МЕТОДОЛОГИЯ РАБОТЫ

### Недельные спринты:

**Цикл:**
1. Ставим план на неделю
2. Выполняем
3. Собираем статистику
4. Анализируем: получилось или нет
5. Делаем выводы: почему не получилось, что улучшить
6. Ставим план на следующую неделю
7. Повторяем

**Формат спринта:**
- Точка А (текущее состояние)
- Точка Б (цель через неделю)
- Анализ: достигли ли точки Б

## 📈 ОТЧЁТНОСТЬ

### Формат отчётов:

#### 1. Дашборд (основной):
**Полная картина проекта:**
- Текущий статус
- Метрики
- Задачи (в работе, в бэклоге)
- Стратегия
- Цели
- Прогресс спринта

#### 2. Ежедневный отчёт в Telegram:
**Краткий review основных метрик:**
- От бота (на базе OpenAI можно сделать)
- Ежедневно утром
- Основные метрики за вчера

### Ключевые метрики:

#### Обязательные (определяются с клиентом):

1. **ROMI (Return on Marketing Investment)** - возврат инвестиций в маркетинг
   - Окупаемость маркетинга

2. **CAC (Customer Acquisition Cost)** - стоимость привлечения пациента/клиента

3. **LTV (Lifetime Value)** - сколько получаем с клиента по услуге

#### Дополнительные метрики:

4. **Посещаемость** (общая и по каналам)
5. **Упоминания в медиа**
6. **Количество звонков** (по каналам)
7. **Количество лидов** (по каналам)
8. **Стоимость лида** (по каналам)
9. **Квалифицированные vs неквалифицированные лиды**
10. **Воронки конверсии**

### Частота обновлений:

- **Минимум:** Ежедневно (краткий отчёт)
- **Основной:** Недельный спринт (полный анализ)

## ✅ QUALITY VALIDATION

### Критерии качества:

**Основной принцип:** Data-driven подход
- Ориентация на метрики
- Решения на основе данных

### Проверка гипотез:

**Система оценки гипотез:**
- 🟢 **Зелёная** - гипотеза полностью рабочая → масштабируем
- 🔴 **Красная** - гипотеза не рабочая → отказываемся
- 🟡 **Жёлтая** - требует улучшений → анализируем и корректируем

### Действия при низком качестве:

1. **Анализ:** Что можно улучшить?
2. **Решение:**
   - Пробуем улучшить (если есть потенциал)
   - Отказываемся от гипотезы (если не рабочая)

### Автоматизация:

**Первый этап (сейчас):**
- ❌ Автоматическая переделка НЕ нужна
- ✅ Всегда спрашивать владельца агентства

**Второй этап (потом):**
- Автоматизируем после отладки системы

## ✅ УТОЧНЕНИЯ (2026-05-08)

### 1. Роль Magisters - ОБУЧЕНИЕ И КОНТРОЛЬ КАЧЕСТВА

**Решение:** Magisters = Учителя и контролёры качества

**Архитектура обучения:**
```
Teacher Agent (собирает знания от Architect)
    ↓
Magisters (обучают и контролируют качество)
    ↓
Orchestrators (координируют выполнение)
    ↓
Subagents (конкретные исполнители)
```

**Роль Magister:**
- ❌ НЕ исполняет задачи сам
- ✅ Обучает Orchestrators и Subagents
- ✅ Следит за качеством работы своего направления
- ✅ Получает знания от Teacher Agent
- ✅ Сортирует информацию в свой Obsidian vault по теме
- ✅ Передаёт знания вниз по цепочке

**Пример: SEO Magister**
- Получает знания о SEO от Teacher
- Обучает SEO Orchestrator
- Контролирует качество работы всей SEO-цепочки:
  - Keyword Agent
  - Content Optimizer Agent
  - Technical SEO Agent

**Правильная цепочка:**
```
Operator → SEO Magister (обучает и контролирует)
              ↓
          SEO Orchestrator (координирует)
              ↓
          ├── Keyword Agent (исполняет)
          ├── Content Optimizer Agent (исполняет)
          └── Technical SEO Agent (исполняет)
```

### 2. Зависимости задач - УМНЫЙ OPERATOR

**Решение:** Operator сам выстраивает цепочку зависимостей (вариант A)

**Требование:** Operator должен быть умным и понимать бизнес-логику

**Пример: "Запусти новую услугу X"**

**Правильная цепочка (с CustDev):**
```
1. Brand Magister → CustDev (Customer Development)
   - Формулировки из кастдевов
   - Tone of Voice
   - Позиционирование

2. Intelligence Magister → Market Research
   - Исследование рынка
   - Анализ конкурентов
   - Целевая аудитория

3. SEO Magister → Keyword Research
   - Подбор ключевых слов (зависит от п.1-2)

4. Content Magister → Content Creation
   - Создание контента (зависит от п.1-3)

5. Ads Magister → Campaign Launch
   - Запуск рекламы (зависит от п.1-4)

6. Analytics Magister → Tracking
   - Отслеживание результатов (зависит от п.5)
```

**Принцип работы:**
- Operator использует **шаблоны** для типовых задач
- Шаблоны **продуманные** и учитывают все этапы
- Внутри Magisters → Orchestrators → Subagents генерируется **максимум информации**
- Информация анализируется для грамотного запуска каналов
- Каналы оцениваются, анализируются, собирается статистика
- Движение от недели к неделе на основе данных

**Недостающие Magisters (нужно добавить):**
