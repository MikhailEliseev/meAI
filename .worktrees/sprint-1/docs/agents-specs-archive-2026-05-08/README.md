## 🔑 КЛЮЧЕВЫЕ ПРИНЦИПЫ

### Фундаментальные правила:

1. **Complete Before Next Rule**
   - Доводим до 100% перед переходом к следующей задаче

2. **Quality Over Speed Rule**
   - Качество важнее скорости. Всегда.

3. **Mock Data Rule**
   - Никаких mock данных в production коде

4. **Роль Magisters**
   - ❌ НЕ исполняют задачи сами
   - ✅ Обучают Orchestrators и Subagents
   - ✅ Контролируют качество

5. **Медицинская специфика**
   - Medical Fact-Checker Agent (обязательно!)
   - Два режима: строгий → расслабленный
   - Академические источники

6. **Data-driven подход**
   - Все решения на основе метрик

## 🚀 КАК ИСПОЛЬЗОВАТЬ

### Для реализации Magisters:

1. Прочитать спецификацию Magister
2. Понять роль и назначение
3. Изучить список Subagents
4. Реализовать базовый класс Magister
5. Добавить специфичную логику
6. Интегрировать с Event Bus и Obsidian

### Для создания спецификаций Subagents:

1. Найти упоминания Subagent в спецификации Magister
2. Понять задачи Subagent
3. Определить входные/выходные данные
4. Описать алгоритм работы
5. Определить метрики успеха
6. Создать отдельную спецификацию

### Для экспериментов с моделями:

1. Выбрать Magister для реализации
2. Реализовать с Opus 4.7
3. Реализовать с Sonnet 4.6
4. Реализовать с Haiku 4.5
5. Сравнить качество и стоимость
6. Выбрать оптимальную модель
