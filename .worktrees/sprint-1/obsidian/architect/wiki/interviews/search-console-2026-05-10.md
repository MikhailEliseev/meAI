## Финальное определение

**Search Console Agent = Глаза системы в поисковых системах**

- Собирает данные из Google Search Console и Яндекс Вебмастера
- Показывает, как сайт показывается в поисковой выдаче (запросы, позиции, показы, клики, CTR)
- Отслеживает проблемы индексации, ошибки сканирования, штрафы
- Передаёт данные в сыром виде для анализа верхнего уровня

## Блок 1: Роль и уникальность

**Q1: Что делает Search Console Agent?**

A: Агент работает с Google Search Console и Яндекс Вебмастером. Собирает данные о том, как сайт показывается в поисковой выдаче: по каким запросам, на каких позициях, сколько показов и кликов. Отслеживает проблемы индексации, ошибки сканирования, штрафы от поисковых систем. Это глаза системы в поисковых системах — видим, как поисковики видят наш сайт.

**Q2: Почему это критично для системы?**

A: Без этих данных мы слепые. Web Analytics показывает, кто пришёл на сайт, но Search Console показывает, кто НЕ пришёл — сколько показов было, но кликов не было (низкий CTR). Показывает проблемы индексации (страницы не попали в индекс), ошибки сканирования (поисковик не может прочитать страницу), штрафы (сайт понижен в выдаче). Это критично для SEO — без этого не понять, почему трафик не растёт.

**Q3: Что агент НЕ делает?**

A:
- ❌ Не собирает метрики трафика (это Web Analytics Agent)
- ❌ Не анализирует конкурентов (это Competitor Analysis Agent)
- ❌ Не делает выводы и рекомендации (это SEO Magister)
- ✅ Только собирает данные из Search Console и Вебмастера, передаёт наверх

## Блок 2: Входные данные и источники

**Q4: Какие данные нужны агенту для работы?**

A:

**Обязательные источники:**
- **Google Search Console API** — запросы, показы, клики, позиции, CTR, проблемы индексации
- **Яндекс Вебмастер API** — запросы, показы, клики, позиции, CTR, проблемы индексации

**Обязательные параметры:**
- `site_url: str` — URL сайта
- `project_id: str` — ID проекта
- `google_search_console_token: str` — токен Google Search Console
- `yandex_webmaster_token: str` — токен Яндекс Вебмастера
- `date_from: date` — начало периода
- `date_to: date` — конец периода

**Q5: Есть ли специфичные требования к входным данным?**

A: Стандартная валидация (URL, токены, даты). Специфичных требований нет.

## Блок 3: Алгоритм и логика

**Q6: Какие основные шаги выполняет агент?**

A:

1. **Сбор данных из Google Search Console** (запросы, показы, клики, позиции, CTR)
2. **Сбор данных из Яндекс Вебмастера** (запросы, показы, клики, позиции, CTR)
3. **Сбор проблем индексации** (страницы не в индексе, ошибки сканирования, штрафы)
4. **Объединение данных** (по запросам, по страницам)
5. **Передача данных дальше** (SEO Magister через Event Bus)

**Q7: Есть ли специфичная логика обработки?**

A: Специфичной логики нет. Стандартная обработка: fetch → process → save.

Возможно, нужно будет объединять данные по запросам (если один запрос есть и в Google, и в Яндексе) — но это простое объединение по ключу.

**Q8: Какие внешние API/сервисы используются?**

A:

**Обязательные API:**
- **Google Search Console API** — данные о поисковой выдаче Google
- **Яндекс Вебмастер API** — данные о поисковой выдаче Яндекса

Rate limits нужно уточнить в документации API.

## Блок 4: Результаты и метрики

**Q9: Что агент возвращает в результате?**

A:

**Результат:**
- Список запросов с метриками (запрос, показы, клики, CTR, средняя позиция) — отдельно Google, отдельно Яндекс
- Список страниц с метриками (URL, показы, клики, CTR)
- Проблемы индексации (страницы не в индексе, ошибки сканирования, штрафы)
- Динамика по дням (показы, клики, CTR, позиции)

**Куда сохраняется:**
- База данных (структурированные метрики)
- Obsidian vault (история, проблемы, инсайты)

**Q10: Как измерять качество работы агента?**

A: Специфичных метрик нет. Стандартные:
- Success rate > 95%
- Execution time (зависит от объёма данных)
- Покрытие источников (оба API доступны)

## Блок 5: Особенности и edge cases

**Q11: Есть ли специфичные ошибки или edge cases?**

A: Специфичных ошибок нет. Стандартные:
- API_UNAVAILABLE (Google Search Console, Яндекс Вебмастер недоступны)
- TIMEOUT (долгий сбор данных)
- INVALID_INPUT (неверный URL, токены)
- RATE_LIMIT_EXCEEDED (превышен лимит запросов к API)

**Q12: Есть ли особенности интеграции с Magister?**

A: Стандартный подход через Event Bus:
- Получает задачи от SEO Magister через `seo.search_console.requested`
- Отправляет результаты через `seo.search_console.completed`
- Correlation ID для трейсинга
- Логирование в Event Store

Специальных требований нет.

## Инсайты и решения

**Ключевые решения:**

1. **Глаза в поисковых системах** — видим, как поисковики видят наш сайт
2. **Два источника** — Google Search Console + Яндекс Вебмастер
3. **Запросы и страницы** — метрики по запросам (показы, клики, CTR, позиции) и по страницам
4. **Проблемы индексации** — страницы не в индексе, ошибки сканирования, штрафы
5. **Динамика** — показы, клики, CTR, позиции день за днём
6. **Сырые данные** — возвращает данные в сыром виде, без выводов
7. **Передача наверх** — данные передаются SEO Magister для анализа

**Границы ответственности:**
- ✅ Собирает данные из Search Console и Вебмастера
- ✅ Отслеживает проблемы индексации
- ❌ НЕ делает выводы (это задача SEO Magister)
- ❌ НЕ анализирует конкурентов
