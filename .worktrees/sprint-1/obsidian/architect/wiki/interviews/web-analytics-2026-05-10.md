## Финальное определение

**Web Analytics Agent = Главный аналитик системы**

- Собирает метрики со всех счётчиков и источников (Яндекс Метрика, Google Analytics)
- Отслеживает отклонения и аномалии
- Анализирует источники трафика и конверсии
- Определяет, какие источники приносят результат
- Передаёт данные в сыром виде для анализа верхнего уровня

---

## Блок 1: Роль и уникальность

**Q1: Что делает Web Analytics Agent?**

A: Главный аналитик системы. Собирает метрики со всех счётчиков и источников (Яндекс Метрика, Google Analytics). Отслеживает отклонения, анализирует источники трафика, смотрит конверсии. Определяет, какие источники приносят пациентов (результат), а какие нет.

**Q2: Почему это критично для системы?**

A: Это все данные (data). Без аналитики невозможно понять:
- Куда мы движемся
- Что работает, что нет
- Какие решения принимать

Данные = основа для всех решений в SEO стратегии.

**Q3: Что агент НЕ делает?**

A:
- ❌ Не имплементирует данные (не внедряет изменения)
- ❌ Не даёт рекомендации и выводы (это задача более верхнего уровня — SEO Magister или Operator)
- ✅ Только собирает и анализирует данные, отслеживает отклонения

---

## Блок 2: Входные данные и источники

**Q4: Какие данные нужны агенту для работы?**

A:

**Основные источники:**
- **Яндекс Метрика** — максимальное количество данных (трафик, источники, конверсии, поведение)
- **Google Analytics** — максимальное количество данных (сессии, пользователи, цели, e-commerce)

**Дополнительные источники:**
- Статистика других сервисов (если есть)

**Обязательные параметры:**
- `site_url: str` — URL сайта для анализа
- `project_id: str` — ID проекта
- `yandex_metrika_token: str` — токен Яндекс Метрики
- `google_analytics_token: str` — токен Google Analytics

**Q5: Есть ли специфичные требования к входным данным?**

A: Специфичных требований нет. Стандартная валидация (URL, токены API).

**Дополнительные источники (опционально):**
- **Яндекс Вебмастер** — данные из поисковой выдачи Яндекса
- **Google Search Console** — данные из поисковой выдачи Google

---

## Блок 3: Алгоритм и логика

**Q6: Какие основные шаги выполняет агент?**

A:

1. **Сбор данных со всех источников** (Яндекс Метрика, Google Analytics, опционально Вебмастер и Search Console)
2. **Усреднение данных** (если есть расхождения между источниками)
3. **Отслеживание отклонений** (аномалии, резкие изменения)
4. **Проверка ошибок получения** (API недоступны, данные неполные)
5. **Передача данных дальше** (на анализ верхнего уровня — SEO Magister)

Агент НЕ делает выводы — только собирает и передаёт данные.

**Q7: Есть ли специфичная логика обработки?**

A: Специфичной логики нет. Стандартная обработка: fetch → process → save.

**Q8: Какие внешние API/сервисы используются?**

A:

**Обязательные API:**
- **Яндекс Метрика API** — метрики трафика, источники, конверсии
- **Google Analytics API** — сессии, пользователи, цели, поведение

**Опциональные API:**
- **Яндекс Вебмастер API** — данные из поисковой выдачи Яндекса
- **Google Search Console API** — данные из поисковой выдачи Google

## Блок 4: Результаты и метрики

**Q9: Что агент возвращает в результате?**

A:

**Результат:**
- Цифры в сыром виде (показатели)
- Статистика день за днём
- Метрики со всех источников

**Куда сохраняется:**
- База данных (структурированные метрики)
- Obsidian vault (история, динамика)

**Q10: Как измерять качество работы агента?**

A: Специфичных метрик нет. Стандартные метрики:
- Success rate > 95%
- Execution time (зависит от объёма данных)
- Покрытие источников (все API доступны)

---

## Блок 5: Особенности и edge cases

**Q11: Есть ли специфичные ошибки или edge cases?**

A: Специфичных ошибок нет. Стандартные:
- API_UNAVAILABLE (Яндекс Метрика, Google Analytics недоступны)
- TIMEOUT (долгий сбор данных)
- INVALID_INPUT (неверный URL, токены)
- RATE_LIMIT_EXCEEDED (превышен лимит запросов к API)

**Q12: Есть ли особенности интеграции с Magister?**

A: Стандартный подход через Event Bus:
- Получает задачи от SEO Magister через `seo.web_analytics.requested`
- Отправляет результаты через `seo.web_analytics.completed`
- Correlation ID для трейсинга
- Логирование в Event Store

Специальных требований к координации нет.
