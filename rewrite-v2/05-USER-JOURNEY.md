# 05 — ПУТЬ КЛИЕНТА (User Journey)

**Дата:** 1 июля 2026
**Статус:** Канон UX

---

## 🎯 ПОЛНЫЙ ПУТЬ КЛИЕНТА (15 шагов)

```
Шаг 1  → Клиент открывает iamaim.ru
Шаг 2  → Видит лендинг + чат-виджет
Шаг 3  → Открывает чат (или пишет сразу)
Шаг 4  → Hermes приветствует
Шаг 5  → Клиент отправляет URL
Шаг 6  → Hermes запускает run_full_scout
Шаг 7  → Прогресс-бар стримит фазы (5-8 минут)
Шаг 8  → Hermes формирует 3 финальных сообщения
Шаг 9  → Клиент кликает ссылку отчёта
Шаг 10 → Открывается standalone HTML отчёт
Шаг 11 → Клиент исследует (scroll, theme toggle)
Шаг 12 → Доходит до CTA
Шаг 13 → (Опционально) Связывается с Михаилом
Шаг 14 → (Опционально) Hermes собирает контакт
Шаг 15 → Транзакция завершена
```

## ШАГ 5: Клиент даёт URL

Клиент: `"https://my-clinic.ru"`

ИЛИ

Клиент: `"посмотрите my-clinic.ru и ещё diamond-clinic.ru"`

### Что Hermes делает автоматически

1. Извлекает URL (regex: `https?://[^\s]+` или `[a-z0-9-]+\.(ru|com|org)`)
2. Если нет протокола — добавляет `https://`
3. Если это НЕ клиника (например, github.com) — мягко уточняет
4. Если это государственная клиника (содержит `gauz`, `gbuz`, `muz`) — вежливо отказывает
5. Если это коммерческая клиника — **ВЫЗЫВАЕТ run_full_scout**

### Пример отказа (государственная)

> "К сожалению, я специализируюсь только на коммерческих клиниках (ООО, АО, ИП). Для государственных учреждений (ГАУЗ, ГБУЗ) мой анализ будет неактуален. Если у вас есть частная клиника — присылайте URL, с радостью разберу."

## ШАГ 6: Запуск pipeline

### Что делает Hermes

Вызывает **ТОЛЬКО** `run_full_scout` с параметрами:

```python
run_full_scout(
    url="https://my-clinic.ru",
    client_name="",  # определится из prescan
)
```

### Что НЕ делать

- ❌ НЕ вызывать `find_competitors` отдельно
- ❌ НЕ вызывать `run_prescan` отдельно
- ❌ НЕ вызывать `quick_overview` отдельно
- ❌ НЕ комментировать ход pipeline текстом в чат
- ❌ НЕ дублировать прогресс (frontend progress bar уже стримит)

### Что отвечает клиенту СРАЗУ после вызова

> "Запускаю разбор вашей клиники. Это займёт ~6-8 минут. Покажу прогресс в реальном времени."

(Одно короткое сообщение —pipeline сам стримит прогресс через SSE.)

### Whisper-комментарии (опционально, по мере находок)

Во время фаз Hermes может отправлять короткие "whisper" сообщения:

- Фаза 1 завершена: "Нашёл 5 конкурентов в радиусе 2 км"
- Фаза 2 завершена: "Сайт грузится 4.5с — это медленно"
- Фаза 3 завершена: "У вас 12 отзывов, у лидера 87"
- Фаза 5 завершена: "Активный Instagram — 12 постов за месяц"

**Правило:** whisper только если есть конкретная находка. Не "Фаза завершена успешно". Минимум — 2-3 whisper за весь pipeline, не больше.

## ШАГ 8: Финальные 3 сообщения

**КРИТИЧНО:** ровно 3 сообщения. Не 2, не 5.

### Сообщение 1 — КОНТРАСТ (макс 500 символов)

**Тон:** жёсткий, конкретный, с цифрами. Старший маркетолог-стратег вскрывает проблемы.

**Структура:**
- ОДИН самый сильный контраст
- "[Имя], смотрите: [факт-шок]. А при этом [противоположный факт-косяк]."

**Пример:**
> "Иван, смотрите: выручка 4 млрд — а сайт грузится 5 секунд и теряет 30% пациентов ещё до звонка. Конкурент X делает в 3 раза меньший оборот, но имеет 4.8 рейтинг на 2ГИС против вашего 4.2."

### Сообщение 2 — ТОЧКИ РОСТА (макс 600 символов)

**Структура:**
- Три главных направления
- С пронумерованным списком
- Каждое = конкретное действие + ожидаемый эффект

**Пример:**
> "Три главных направления:
>
> 1. Скорость сайта — -2.5 секунды = +15% конверсии заявок
> 2. Контент по косметологии — вы пишете 1 пост/месяц, лидер 8. Догоните за 3 месяца
> 3. Отзывы на ПроДокторов — у вас 12, у лидера 87. Это 7x упущенных пациентов"

### Сообщение 3 — ОТЧЁТ (макс 400 символов)

**Структура:**
- Ссылка на отчёт (короткая, чистая)
- Что внутри (10 секций)
- Soft handoff

**Пример:**
> "Полный разбор доступен:
> https://iamaim.ru/gkzrghmz
>
> 10 секций: рынок, конкуренты, тех.аудит, отзывы, контент, врачи, СМИ, финансы, рекомендации, контент-план. Без обязательств — просто посмотрите.
>
> Если захотите углубиться — пишите."

### Что НЕ писать в финальных сообщениях

- ❌ "Купите наши услуги"
- ❌ "Закажите аудит"
- ❌ "Скидка 20% до конца недели"
- ❌ "Прайс на услуги"
- ❌ "Свяжитесь с нашим менеджером"
- ❌ Эмодзи-спам (максимум 1 эмодзи на сообщение)
- ❌ "Спасибо за использование AIM"

## ШАГ 9: Клиент кликает ссылку

### Что происходит

```
Клиент кликает https://iamaim.ru/gkzrghmz
→ Nginx → WordPress → index.php
→ index.php: 8-char slug, DOCTYPE html, </html>  → ✅ scout report
→ header Content-Type: text/html
→ header Content-Length: {strlen байты}
→ echo $post->post_content; exit;
```

### latency

- TTFB: <300ms (MariaDB кеш + PHP-FPM)
- Total: зависит от размера HTML (~50 KB → 100ms на 4G)

## ШАГ 11: Исследование отчёта

### Что делает клиент

1. Скроллит сверху вниз
2. Видит секции с метриками, конкурентами, сильными/слабыми сторонами
3. Кликает theme toggle (light → dark и обратно)
4. Может распечатать (Cmd+P)
5. Может поделиться ссылкой

### Секции в отчёте (10 шт)

1. **Hero** — название клиники, дата, город
2. **Ключевые метрики** — 4-6 stat cards
3. **Рынок** — Perplexity research summary
4. **Конкуренты** — 3-5 cards с бейджами
5. **Технический аудит** — Lighthouse scores, speed, mobile-friendly
6. **Отзывы** — 2ГИС, Яндекс.Карты, ПроДокторов
7. **Контент-анализ** — что пишут, как часто, какие темы
8. **Врачи** — публичные персоны, регалии, соцсети
9. **СМИ-упоминания** — Forbes, РБК, Vademecum
10. **Финансы** — ГИР БО выручка, прибыль, динамика

Дополнительно (опционально):
- **Боли пациентов** (форумы)
- **HeadHunter анализ**
- **Контент-план** (рекомендации)

### Структура каждой секции

```html
<section class="section">
  <div class="sec-tag">Раздел 0X — {название}</div>
  <h2>{Заголовок}</h2>

  <!-- Краткий summary -->
  <div class="glass-card">
    <p>Главный вывод секции — ОДНО предложение.</p>
  </div>

  <!-- Данные (таблицы, метрики, бейджи) -->
  ...

  <!-- Интерпретация -->
  <div class="surface-block surface-block-{green|red}">
    <p>Что это значит для бизнеса клиента.</p>
  </div>
</section>
```

## ШАГ 15: Транзакция завершена

### Возможные исходы

1. ✅ Клиент доволен отчётом → связался с Михаилом → платная экспертиза

### Метрика успеха

- 100 отчётов сгенерировано за месяц
- 10% обратились к Михаилу
- 3% стали платными клиентами

## 🎬 EDGE CASES

### Edge 1: URL не клиники

Клиент: `"https://github.com"`

> Hermes: "Не похоже на сайт клиники. AIM анализирует только медицинские клиники. Если у вас клиника — присылайте её URL."

### Edge 2: URL государственная клиника

Клиент: `"https://gauz-moskva.ru"`

> Hermes: "К сожалению, я работаю только с коммерческими клиниками (ООО, АО, ИП). Для государственных учреждений мой анализ будет неактуален."

### Edge 3: URL не отвечает

Pipeline фаза 0: `"URL не отвечает. Проверьте правильность адреса."`

> Hermes: "Не удалось получить данные с сайта {url}. Проверьте правильность адреса или доступность сайта."

### Edge 4: Pipeline упал на середине

PipelineEngine ловит ошибку, возвращает partial results.

> Hermes: "Разбор завершён частично: 8 из 13 фаз. Отчёт доступен по ссылке, но некоторые секции могут быть неполными. Хотите, чтобы я попробовал ещё раз?"

### Edge 5: Клиент дал 2 URL (свой + конкурент)

> Hermes: "Понял. {url1} — ваш сайт, {url2} — конкурент. Запускаю разбор по вашему сайту, а конкурента добавлю в секцию сравнения."

Pipeline использует `url1` как primary, `url2` как additional competitor.

### Edge 6: Pipeline занял больше 10 минут

SSE deadline = 600s. Если pipeline не успевает:

> Hermes: "Разбор занимает больше обычного. Продолжаю в фоне — ссылка на отчёт придёт в течение 5 минут."

Фоновый режим через `run_background_pipeline` tool (опционально для v2.0).

### Edge 7: Голосовое сообщение в Telegram

AssemblyAI транскрипция → текст → обычная обработка.

> Hermes: "Распознал голос: '{transcript}'. Запускаю разбор."

### Edge 8: Клиент спрашивает про услуги AIM

Клиент: "Сколько стоит?"

> Hermes: "Базовый разбор сайта — бесплатно (то что вы сейчас получите). Платная экспертиза — индивидуально, зависит от задач. Сначала пройдите бесплатный разбор, потом решите нужно ли углубление."
