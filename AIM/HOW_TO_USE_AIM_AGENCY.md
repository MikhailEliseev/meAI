# Руководство: Как взаимодействовать с AIM Agency

**Created:** 2026-05-04T21:55 GMT+3

## 🎯 Архитектура взаимодействия

```
User (ты)
    ↓
    ├─→ Architect (Эобер) ─→ стратегия + планирование
    │       ↓
    │   Operator ─→ тактическое выполнение
    │       ↓
    │   Magisters (SEO, Content, Ads) ─→ координация
    │       ↓
    │   Subagents (CI система и др.) ─→ выполнение
    │
    └─→ Operator (напрямую) ─→ быстрое выполнение
```

## 📋 Когда обращаться к ARCHITECT (Эоберу)

### ✅ Используй Architect для:

**1. Стратегических задач:**
- Разработка маркетинговой стратегии
- Анализ рынка и конкурентов с рекомендациями
- Планирование кампаний
- Выбор каналов продвижения
- Распределение бюджета

**2. Комплексных проектов:**
- Требуют анализа + планирования + выполнения
- Несколько этапов работы
- Координация между Magisters
- Долгосрочное планирование

**3. Экспертных решений:**
- "Что лучше: SEO или контекст для этой ниши?"
- "Как распределить бюджет между каналами?"
- "Какую стратегию выбрать?"

### 🎯 Что делает Architect:

1. Анализирует задачу
2. Создаёт стратегический план
3. Координирует Magisters
4. Использует CI инсайты для решений
5. Принимает стратегические решения
6. Возвращает план действий + рекомендации

### 📝 Примеры запросов к Architect:

```
"Эобер, проанализируй рынок стоматологии в Москве и предложи 
стратегию продвижения для новой клиники с бюджетом 500k"

"Эобер, нужно выйти на рынок косметологии. Проанализируй конкурентов
и скажи, какие каналы использовать и как позиционироваться"

"Эобер, у клиента падают продажи. Проанализируй что делают конкуренты
и предложи план по улучшению ситуации"
```

## 📋 Когда обращаться к OPERATOR (напрямую)

### ✅ Используй Operator для:

**1. Тактических задач:**
- Найти ключевые слова
- Создать контент
- Настроить рекламу
- Проанализировать конкурентов
- Запустить CI анализ

**2. Быстрого выполнения:**
- Чёткая задача без планирования
- Одна конкретная операция
- Не требует координации
- Известен результат

**3. Прямого делегирования:**
- "SEO Magister, сделай аудит"
- "Content Magister, создай план"
- "Ads Magister, запусти кампанию"

### 🎯 Что делает Operator:

1. Выполняет конкретные задачи
2. Делегирует Magisters
3. Координирует выполнение
4. Возвращает результаты (без стратегии)

### 📝 Примеры запросов к Operator:

```
"Operator, запусти CI анализ для стоматологии в Москве"

"Operator, найди 20 ключевых слов для ниши косметология"

"Operator, создай 5 статей для блога клиники"

"Operator, сгенерируй коммерческое предложение на основе 
последнего CI анализа"
```

## 🚀 Рекомендация для CI системы

### Первое использование: Через ARCHITECT ⭐

**Запрос:**
```
Эобер, мне нужно проанализировать конкурентов в нише [стоматология, Москва]
и получить рекомендации по маркетинговой стратегии. 

Используй новую CI систему для глубокого анализа конкурентов,
а затем предложи стратегию на основе полученных инсайтов.
```

**Что произойдёт:**
1. Architect получит запрос
2. Создаст план анализа
3. Делегирует Operator → CI Orchestrator
4. CI система выполнит анализ (15 агентов)
5. Architect получит CI инсайты
6. Создаст стратегию на основе данных
7. Вернёт готовую стратегию + план действий

**Плюсы:**
- ✅ Architect использует CI инсайты для стратегии
- ✅ Получишь не только данные, но и рекомендации
- ✅ Комплексный подход
- ✅ Показывает полную ценность системы
- ✅ Magisters получат CI контекст для работы

**Минусы:**
- ⏱️ Дольше (но качественнее)

---

### Последующие использования: Через OPERATOR

**Запрос:**
```
Operator, запусти Quick CI анализ для [ниша]
```

**Что произойдёт:**
1. Operator делегирует CI Orchestrator
2. CI система выполнит анализ
3. Вернёт JSON результаты
4. Ты сам интерпретируешь данные

**Плюсы:**
- ✅ Быстрее
- ✅ Прямой доступ к данным
- ✅ Меньше промежуточных слоёв

**Минусы:**
- ❌ Нет стратегических рекомендаций
- ❌ Нужно самому анализировать результаты

## 📊 Сравнение подходов

| Критерий | Architect | Operator |
|----------|-----------|----------|
| Скорость | Медленнее | Быстрее |
| Результат | Стратегия + данные | Только данные |
| Рекомендации | ✅ Да | ❌ Нет |
| Координация | ✅ Magisters | ⚠️ Ограниченная |
| CI интеграция | ✅ Полная | ⚠️ Базовая |
| Для первого раза | ⭐ Рекомендуется | Не рекомендуется |
| Для повторных | Опционально | ⭐ Рекомендуется |

## 🎯 Практические сценарии

### Сценарий 1: Новый клиент (используй Architect)

**Задача:** Разработать стратегию для новой клиники

**Запрос:**
```
Эобер, у меня новый клиент - стоматологическая клиника в Москве.
Бюджет 500k на 3 месяца. Нужна полная стратегия продвижения.

Проанализируй конкурентов через CI систему и предложи:
1. Позиционирование
2. Каналы продвижения
3. Распределение бюджета
4. План на 3 месяца
```

**Результат:** Полная стратегия с обоснованием

---

### Сценарий 2: Быстрый анализ (используй Operator)

**Задача:** Получить список конкурентов

**Запрос:**
```
Operator, запусти Quick CI анализ для стоматологии в Москве.
Нужен список конкурентов и базовые метрики.
```

**Результат:** JSON с данными

---

### Сценарий 3: Оптимизация кампании (используй Architect)

**Задача:** Улучшить результаты текущей кампании

**Запрос:**
```
Эобер, текущая рекламная кампания даёт CAC 5000 руб, 
а нужно 3000 руб. 

Проанализируй что делают конкуренты и предложи 
как оптимизировать кампанию.
```

**Результат:** План оптимизации с рекомендациями

---

### Сценарий 4: Регулярный мониторинг (используй Operator)

**Задача:** Еженедельный анализ конкурентов

**Запрос:**
```
Operator, запусти Quick CI анализ для отслеживания изменений
у конкурентов за последнюю неделю.
```

**Результат:** Обновлённые данные

## 💡 Итоговые рекомендации

### Для первого использования CI системы:

**✅ Обратись к ARCHITECT (Эоберу)**

Почему:
1. Покажет полную ценность CI системы
2. Даст стратегию, а не только данные
3. Magisters получат CI контекст
4. Увидишь как всё работает вместе

### Для последующих использований:

**Выбирай в зависимости от задачи:**

- **Architect** → когда нужна стратегия и рекомендации
- **Operator** → когда нужны только данные

### Золотое правило:

```
Стратегия + Планирование = Architect
Выполнение + Данные = Operator
```

## 🔄 Workflow для CI системы

### Первый раз (через Architect):

1. Ты → Architect: "Проанализируй конкурентов и дай стратегию"
2. Architect → Operator: "Запусти CI анализ"
3. Operator → CI Orchestrator: "Выполни Deep анализ"
4. CI система → 15 агентов работают
5. Результаты → Operator → Architect
6. Architect → анализирует + создаёт стратегию
7. Architect → Тебе: "Вот стратегия + план"

### Последующие разы (через Operator):

1. Ты → Operator: "Запусти CI анализ"
2. Operator → CI Orchestrator: "Выполни Quick анализ"
3. CI система → работает
4. Результаты → Operator → Тебе: "Вот данные"
