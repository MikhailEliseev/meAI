<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Perplexity API | External LLM service — prompt text is trusted (authored by us), but API responses cross trust boundary. JSON parsing must be defensive. |
| client → Hermes | Untrusted user input (URLs, messages) flows through Hermes to Perplexity — URL validation required before sending to external API. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01 | Spoofing | quick_overview tool | mitigate | Validate Perplexity API key at tool init; handle 401/403 with clear error message |
| T-32-02 | Tampering | Perplexity API response | mitigate | Parse JSON defensively with try/except; validate response structure before using data |
| T-32-03 | Information Disclosure | prompt files | mitigate | Prompt files contain only static text (no secrets); PERPLEXITY_API_KEY read from env at runtime |
| T-32-04 | Denial of Service | quick_overview timeout | mitigate | 15-second httpx timeout prevents hanging; asyncio.gather with prescan ensures one slow path doesn't block the other |
| T-32-05 | Elevation of Privilege | Instrumentator removal | accept | Removing Instrumentator eliminates a crash vector; custom /metrics endpoint and custom prometheus_client metrics remain — no elevation risk |
| T-32-SC | Tampering | pip install openai | mitigate | Package from PyPI (openai), widely trusted; slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] |
</threat_model>
