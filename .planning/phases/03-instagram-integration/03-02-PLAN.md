Add a "mini-call" LLM invocation between Pass 1 (Collect) and Pass 2 (Gap-analyze) that determines whether the clinic is Instagram-critical. The verdict populates `state.niche` and feeds downstream logic in Plan 03-03 (Pass 1 prompt augmentation + Pass 2 hard FAIL QC gate).

Purpose: Decisions D-01 + D-02 + D-03 specify the detection mechanism — LLM-based (not keyword/ОКВЭД), mini-call pattern (short, ~5s), with a boundary rule that excludes partial-aesthetic clinics (e.g., dental with add-on esthetic services). This plan implements only the detection plumbing; enforcement logic lives in Plan 03-03.

Output: New `niche_detector.py` module; modified `states.py` (new field); modified `three_pass.py` (mini-call invocation).

## Phase Goal (MVP)

**As a** Hermes orchestrator,
**I want to** know whether the current clinic is Instagram-critical BEFORE I run Pass 2 gap analysis,
**so that** Pass 2 can apply the hard-FAIL QC rule for missing Instagram data only when it actually matters (per D-04).

## User Story (Vertical Slice)

After this plan, when a presale starts for `iphk.ru` (plastic surgery), the orchestrator logs:
```
Niche detection: instagram_critical=True, niche=plastic_surgery, reason="primary service line"
```
And when a presale starts for a generic dental clinic with one cosmetic dentist, it logs:
```
Niche detection: instagram_critical=False, niche=dental, reason="aesthetic services are add-on, not primary"
```

Plan 03-03 will consume this signal to enforce the mandatory Instagram rule.
