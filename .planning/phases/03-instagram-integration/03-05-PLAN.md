<objective>
Render a transparent "Instagram: данные недоступны — {reason}" block in sections 03 (Experts) and 04 (Content Analysis) when Instagram data is missing for an Instagram-critical niche. Update the QC Coverage HTML section to read `metadata['not_applicable_items']` (populated by Plan 03-06 `_apply_niche_conditional_coverage`) and render those items with neutral styling distinct from `missing`. Close the cross-plan data-contract gap by updating Pass 3 prompt to explicitly instruct the LLM to pass `niche` and `instagram_data` kwargs to `generate_html_report`.

Purpose: Decision D-07 mandates honest, transparent reporting of WHY Instagram data is unavailable. Decision D-08 (HTML side) requires the QC Coverage section to show non-applicable items differently from missing ones — now sourced from the canonical `CoverageReport.not_applicable_items` field (Plan 03-06 Task 1) rather than derived via diff. Checker issue #1 flagged that Pass 3 prompt had no instruction telling the LLM to pass `niche` + `instagram_data` kwargs — this plan closes that gap.

Output: New `_build_no_instagram_block` helper in generate_html_report.py; updated `_build_qc_coverage_section` reading `not_applicable_items`; extended `_build_report_html` with niche + instagram_data kwargs; updated `_build_prompt` in pass_fill_assemble.py with explicit kwargs-passing instruction.
</objective>

## Phase Goal (MVP)

**As a** presale client reading the report,
**I want to** see a clear explanation when Instagram analysis is unavailable,
**so that** I understand WHY (no account / private profile / etc.) rather than wondering if the analyst forgot.

## User Story (Vertical Slice)

After this plan, three scenarios render correctly:

1. **Cosmetology clinic, Instagram-active top-5 found**: sections 03+04 show full Instagram metrics for each doctor (unchanged behavior — Plan 03-04 provides the data).

2. **Cosmetology clinic, NO Instagram data for any doctor** (all handles returned "no data" from Perplexity): section 03 shows the doctors with regalia + a block: "Instagram: данные недоступны — handle не найден в Perplexity index. Вызовы были произведены для 8 handles, ни один не вернул данных." Section 04 shows a similar block: "Instagram: данные недоступны — content analysis невозможна без Instagram-метрик врачей."

3. **Dental clinic** (non-critical niche): sections 03+04 show doctor info from the site (no Instagram attempt). QC Coverage section reads `metadata['not_applicable_items']` (populated by Plan 03-06) and shows item 5 with ⚪ "N/A — не critical ниша" gray badge. Total items shown as 14, not 15.

Pass 3 (pass_fill_assemble.py) explicitly instructs the LLM: "When calling generate_html_report, pass niche=<value from state.collected_data.niche_detection> AND instagram_data=<full run_instagram_content response from Pass 1>".
