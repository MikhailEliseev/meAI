# Phase 23: Ultra-Deep Prescan — Контекст и решения

**Дата:** 2026-06-02
**Источник:** Брейншторм ultra-prescan + обсуждение 3 подходов

## Мотивация

Сейчас prescan делает быстрый анализ (структура сайта, финансы, быстрый SEO, отзывы, соцсети). Этого недостаточно для WOW-эффекта. Клиент должен офигеть от глубины анализа.

Запрос: «Всё, что можно достать из сети, достать» — максимально плотный анализ сайта клиента на этапе PRESALE.

## Архитектурное решение: Подход 2 — Staged Pipeline (ВЫБРАН)

**Почему не Подход 1 (монолитный):**
- Не даёт промежуточных результатов клиенту — 90+ секунд тишины
- Нет театральности («5 агентов работают»)

**Почему не Подход 3 (мультиагентный):**
- 2-3 недели разработки
- Race conditions, потеря сообщений, дублирования в первый месяц
- EventBus и BaseAgent ещё не обкатаны в боевых условиях
- **Backlog: вернуться когда в базе 200+ компаний** (сохранено в auto-memory)

**Подход 2 — Staged Pipeline:**
- Три последовательные стадии с промежуточными результатами
- Progress callback → Hermes → Telegram (чат-сообщения)
- «Театр 5 агентов» для пафоса (маркетинг, не реальная архитектура)
- Все данные → `company_profiles` (JSONB) для накопления базы
- Повторный заход → мгновенная выдача из БД
- Интеграция с существующим PrescanOrchestrator (не замена с нуля)

## Три стадии

### Стадия 1: «Финансовый хук» (20-30 сек)
**Цель:** Сразу показать деньги — это цепляет.
- Структура сайта (существующее)
- ГИР БО (nalog.gov.ru) — оборот, прибыль по годам
- DaData — юрлицо, регистрация, уставной капитал
- **Вывод:** «Оборот X млн, прибыль Y млн, на рынке Z лет»

### Стадия 2: «Под капотом» (40-60 сек)
**Цель:** Показать глубину анализа.
- DaData — учредители, гендиректор
- Росздравнадзор — медицинские лицензии
- Глубокий SEO (sitemap crawl, structured data, schema.org)
- Отзывы (Яндекс.Карты, 2ГИС, ПроДокторов)
- Соцсети (VK, Telegram)
- **Вывод:** «Лицензий X, учредители Y, SEO-проблем Z, отзывов N»

### Стадия 3: «Рынок» (60-90+ сек)
**Цель:** Показать позицию на рынке.
- Яндекс/Google Maps — карточки, рейтинг
- Быстрый поиск конкурентов рядом (гео)
- Многолетние тренды выручки
- Аудит контента (глубокий)
- Анализ изображений (опционально, alt-тексты)
- **Вывод:** «В радиусе X км — Y конкурентов, тренд выручки Z»

## Технические решения

### База данных: company_profiles
- JSONB колонка для гибкости (разные типы компаний = разные поля)
- Ключ: URL + INN (составной)
- Кэширование: повторный заход → мгновенная выдача
- Индексы: GIN на JSONB, B-tree на дату создания

### Progress Callback
- Каждая стадия завершена → callback с результатами
- Hermes получает промежуточные результаты и транслирует в Telegram
- Асинхронный механизм (не блокируем пайплайн ожиданием Telegram)

### Интеграция с PrescanOrchestrator
- Расширяем существующий, не заменяем
- Добавляем stage-параметр и callback
- Новые data source'ы (DaData, Росздравнадзор, Maps) — новые thread'ы
- Сохраняем обратную совместимость

## Что НЕ делаем (out of scope)
- Подход 3 (мультиагентный) — backlog
- Векторные эмбеддинги (ChromaDB) для поиска похожих клиник — отдельная фича потом
- Реальный мультиагентный оркестратор — пока театр
