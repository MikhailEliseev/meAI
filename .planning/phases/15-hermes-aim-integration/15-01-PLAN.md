Create AIM/hermes/scripts/copy_soul.sh — a startup script that copies SOUL.md from the skills directory (mounted read-only in Docker, per D-03) to the HERMES_HOME location where Hermes expects it (per Pitfall 4: load_soul_md() at agent/prompt_builder.py:1308 reads from get_hermes_home() / "SOUL.md").

Script content:
```bash
#!/bin/bash
# copy_soul.sh — ensure SOUL.md is at HERMES_HOME/SOUL.md
# Hermes load_soul_md() function reads from $HERMES_HOME/SOUL.md (hardcoded path)
# Our SOUL.md lives in skills/aim/ which is mounted read-only per D-03
# Solution: copy to HERMES_HOME at container startup

set -euo pipefail

HERMES_HOME="${HERMES_HOME:-/opt/data}"
SOURCE="/opt/hermes/skills/aim/SOUL.md"
TARGET="${HERMES_HOME}/SOUL.md"

if [ ! -f "$SOURCE" ]; then
    echo "[copy_soul] ERROR: SOUL.md not found at $SOURCE" >&2
    exit 1
fi

mkdir -p "$HERMES_HOME"

# Copy if target doesn't exist or source is newer
if [ ! -f "$TARGET" ] || [ "$SOURCE" -nt "$TARGET" ]; then
    cp "$SOURCE" "$TARGET"
    echo "[copy_soul] SOUL.md copied to $TARGET"
else
    echo "[copy_soul] SOUL.md already present at $TARGET"
fi
```

Make it executable: `chmod +x AIM/hermes/scripts/copy_soul.sh`

The Dockerfile in Plan 15-03 will call this script before starting uvicorn. Document in the script comments that this is required because Hermes load_soul_md() (agent/prompt_builder.py:1308) hardcodes the path to `get_hermes_home() / "SOUL.md"` — it does NOT search skills/ subdirectories.
