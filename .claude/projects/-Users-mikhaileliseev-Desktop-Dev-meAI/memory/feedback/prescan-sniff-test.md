**Правило:** Если прескан выдаёт результат, который звучит неправдоподобно для клиента такого уровня (нет мобильной версии в 2026, нет SSL, SEO 0/100, нет H1 вообще), ОБЯЗАТЕЛЬНО делать ручную проверку через `curl -sL URL | grep -i 'viewport\|ssl\|h1\|title'` перед включением этого утверждения в КП.

**Why:** Прескан ошибочно показал `has_mobile_viewport: false` для yutskovskaya.ru из-за бага с наивным substring-поиском (атрибуты в обратном порядке). Это привело к 12 ложным утверждениям в КП, которые клиент мог бы опровергнуть за 5 секунд открытием сайта на телефоне. Правки заняли ~30 минут.

**How to apply:** При генерации КП, после получения данных прескана, для каждого 🔴-статуса делать быструю ручную проверку. 30 секунд проверки экономят 30 минут правок и сохраняют доверие клиента.

**Bug fix:** Баг в `prescan_orchestrator.py:429,1010` исправлен — наивный substring заменён на regex `<meta[^>]*name=["']viewport["']`. Но правило всё равно действует: прескан может ошибаться и в других полях.
