## 🎯 Краткий ответ на твой главный вопрос

**Вопрос:** "Упрощать существующее, сносить и начинать с нуля, или чинить?"

**Ответ:** **Ни то, ни другое.** Делать **radical simplification (кардинальное упрощение)** — это третий путь между "чинить" и "сносить".

**Если одним предложением:** Рабочее ядро у тебя ЕСТЬ и оно ЖИВОЕ — снести = потерять 2 месяца; чинить без удаления = не задышит; нужно хирургически вырезать мёртвое и фокусироваться на одном потоке.

**Хорошее (реально работает):**
- 46 chat запросов за 24h — продукт используется
- Smoke test: POST /api/chat → Hermes ответил за <1с

- 32 сессии в SQLite, 161 сообщение

- Дизайн-система готова (design-showcase-dual-theme.html)
- Monitoring стек полный

**Плохое (что мешает):**
- PostgreSQL auth сломан → backend не пишет в БД → 67 tools получают ошибки при вызове aim-app endpoints
- session_archive баг → данные между фазами не сохраняются → Hermes не видит результаты предыдущих шагов → теряет контекст
- SOUL.md рассинхрон: образ говорит про v4 "3-проходный цикл", volume говорит про "армию 70+ субагентов" → LLM получает mixed signals
- 152 файла deprecated кода → LLM видит всю эту структуру через imports/через контекст → путается

### Главный инсайт

**Твоя боль "Hermes теряет инструменты и не доходит до конца" — НЕ проблема Hermes или LLM. Это проблема ОКРУЖЕНИЯ:**

1. Hermes вызывает tool → tool делает HTTP к aim-app → PostgreSQL 500 → tool возвращает error → Hermes теряет нить
2. Hermes вызывает 14 фаз → session_archive ломается → следующая фаза не видит предыдущую → Hermes не понимает что уже собрано
3. SOUL.md описывает 70+ субагентов → Hermes думает "мне надо их вызывать" → пытается → не находит → фрустрируется
4. 67 tools в реестре → LLM видит 67 вариантов → соблазн вызвать не тот

**Убери эти 4 препятствия — Hermes дойдёт до конца pipeline.**

## 🚫 Почему НЕ сносить (Путь B)

| Аргумент за снос | Контр-аргумент |
|---|---|
| "Система перегружена" | Перегрузка ВНЕ ядра. Ядро = 4 контейнера |
| "Много миллиона интеграций" | Активно используются ~10. Остальное можно удалить |
| "Новый сервер = чистый старт" | Те же 67 tools будут теми же. Проблема не в сервере |
| "Чистый Hermes = проще" | У тебя уже есть настроенный Hermes. Зачем пересобирать? |

**Цена Path B:** 1-2 недели даунтайма + перенос 29 API ключей + переконфиг nginx/ssl + потеря 32 сессий + перенос WordPress (90 страниц). **И в конце те же проблемы с архитектурой.**

---

## 🚫 Почему НЕ "просто чинить" (Путь A)

| Аргумент за "чинить" | Контр-аргумент |
|---|---|
| "Минимум изменений" | Без удаления магистров/субагентов LLM продолжит путаться |
| "Бережём время" | Время уже потеряно. 2 месяца ушло на accumulation сложности |
| "Не сломаем рабочее" | Фиксы без чистки = новые костыли на старые |

**Цена Path A:** починишь PG auth → backend "оживёт" → но 152 файла магистров продолжат существовать → LLM продолжит видеть deprecated paths → новая волна багов.

## ✅ Почему Path C (radical simplification) — правильный

**Принцип:** "Минимальное разрушение, максимальный фокус"

### Что сохраняем (10% системы)
- aim-hermes + 67 tools (Hermes app + hermes-agent lib)
- aim-wordpress + aim-theme + MariaDB (WordPress)
- aim-nginx + SSL
- aim-redis (cache)
- Monitoring stack
- Key rotation scripts
- DeepSeek API integration
- Design showcase + chat inline

### Что удаляем (90% "мусора")
- ❌ PostgreSQL (или используем SQLite, или фиксим auth — но тоже можно убрать)
- ❌ aim-app backend (если tools могут работать без него)
- ❌ Все magisters (19 файлов)
- ❌ Все subagents (133 файла)
- ❌ EventBus
- ❌ Pipeline v7 (2692 строки)
- ❌ HeadroomGuard (нет контейнера — удалить конфиги)
- ❌ aim-frontend Next.js (если landing на WordPress)
- ❌ aim-paperclip (если выяснится что не нужен)
- ❌ Teacher agent (если не используется)
- ❌ Obsidian vaults (кроме architect)
- ❌ .venv, .planning, .cache, all *.bak files
- ❌ Все backup-директории

### На чём фокусируемся
**ТОЛЬКО одно:** клиент → URL → Hermes прогоняет run_full_scout → финальный отчёт на сайте.

Не:
- Не CRM
- Не PM
- Не мультиагентность
- Не Telegram sales bot (пока)
- Не analytics dashboard
- Не teacher / self-learning
- Не расширенный onboarding
