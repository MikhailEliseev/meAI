# Guided Configurator — Design Spec

**Дата:** 2026-06-03
**Статус:** draft
**Тема:** Конфигуратор услуг в конце КП + живой presale-диалог Hermes

## 1. Контекст

Текущая схема ценообразования (3-уровневая: Базовый / Оптимальный / Максимальный) отвергнута. Клиенты не хотят быть частью воронки — они хотят решение под себя. Тренд на рынке США: modular pricing (base retainer + plug-and-play modules), guided configuration со smart defaults.

## 2. Концепция

**LEGO-конструктор в конце КП.** Клиент видит услуги, разложенные по 4 категориям. Категории определяются автоматически на основе prescan + CI-анализа. Клиент собирает финальный набор под себя, следуя нашим рекомендациям.

### 2.1 Четыре категории

| Категория | Цвет | Механика | Смысл |
|---|---|---|---|
| **БАЗА** | Зелёный `#1A5C3E` | Заблокирована (🔒) | Без этого нельзя. Фундамент. |
| **РЕКОМЕНДОВАНО** | Золотой `#B8860B` | Предотмечена (✅), можно снять | Без этого бизнес не попрёт. При снятии — мягкое предупреждение. |
| **ОПЦИОНАЛЬНО** | Серый `#6B7280` | Не отмечена (☐), можно добавить | Усилит результат, но можно стартовать без. |
| **СЛЕДУЮЩИЙ ЭТАП** | Синий `#2563EB` | Заблокирована (⏭️) с пояснением | Milestone 2. Не сейчас, но в перспективе. Явно объясняем почему. |

Название «СЛЕДУЮЩИЙ ЭТАП» подчёркивает перспективу проекта (milestone), а не отказ.

### 2.2 Как определяются категории

Категории — результат автоматического prescan + CI-анализа, НЕ ручного подбора.

| Данные prescan | Категоризация |
|---|---|
| У всех клиник | «Аудит + стратегия» → БАЗА |
| SEO < 40 / нет sitemap / нет structured data | «Пересборка сайта» → РЕКОМЕНДОВАНО |
| Нет рекламных кампаний | «Яндекс.Директ» → РЕКОМЕНДОВАНО |
| Выручка < конкурентов на 20-50% | Все рекомендованные → усиленно |
| Контент < 10 страниц | «Блог» → ОПЦИОНАЛЬНО |
| Соцсети не ведутся / бюджет ограничен | «Соцсети» → СЛЕДУЮЩИЙ ЭТАП |

Логика: prescan даёт данные → правила определяют категорию → конфигуратор рендерит.

## 3. Presale-диалог Hermes (7 шагов)

### Шаг 1: Приветствие
Hermes представляется, объясняет что он делает, просит ссылку на сайт.

### Шаг 2: Prescan с live-наррацией (90-180 сек)
Hermes сообщает клиенту о каждом действии:
«Зашёл на сайт → смотрю соцсети → поднимаю финансы → собираю отзывы → определяю ключевых врачей»

### Шаг 3: Картина клиенту
- Выручка, прибыль, тренды
- Ключевые врачи (3-4 персоны, на которых строится выдача / страница врачей)
- Критичные ошибки сайта
- Отзывы (рейтинг, количество, темы похвал/жалоб)

### Шаг 4: Параллельный конкурентный трек
«Пока я копаю глубже — кто ваши реальные конкуренты?»
- Клиент назвал → анализируем названных
- Не назвал → Hermes подбирает сам (Google Maps + DaData + rusprofile) → клиент валидирует: «этих знаю, этих нет»

### Шаг 5: CI-анализ с live-статусами (WOW-эффект)
Постоянное информирование: «Смотрю SEO конкурента X... анализирую цены Y... изучаю врачей Z...»
Клиент видит прогресс. Это главный WOW-момент.

### Шаг 6: Выжимка в чате + полный КП ссылкой

Hermes НЕ пишет КП в чат. Он даёт короткую выжимку и ссылку:

> *«Я всё проанализировал. Если коротко:*
> *1. Пересобрать сайт — SEO 34 из 100, конкуренты на 70+*
> *2. Запустить Яндекс.Директ — 70% пациентов в Липецке ищут через поиск*
> *3. Соцсети — следующий этап, сначала закрываем поиск*
>
> *Цена: 60 000 ₽/мес. Результат: +30% записей через 3 месяца.*
>
> *Вот полный отчёт со всеми данными: [ссылка на HTML-КП]*
>
> *Для более детального обсуждения — поговорите с Михаилом. Он соберёт больше данных, сделаем более глубокое предложение. Если всё устраивает — бьём по рукам и работаем, пока конкуренты не добрались до технологий и жуют сопли.»*

**Тон выжимки:**
- Не просим доверия — показываем найденные косяки. «SEO 34» — это факт, а не мнение.
- Делаем = глаголы действия. «Пересобрать», «запустить», «закрываем».
- Финальная фраза — urgency без паники: конкуренты отстают, но это временно.
- Михаил — следующий шаг для тех, кому нужно глубже. Не «робот», а «я собрал данные, Михаил соберёт ещё больше».

### Шаг 7: Handoff на Михаила

Клиент:
→ пишет «поехали» → Hermes: «Переключаю на Михаила. Он свяжется в ближайшее время.»
→ кликает ссылку на КП → читает → в блоке 10 конфигуратор → отправляет заявку
→ хочет глубже → «Поговорите с Михаилом» → handoff с контекстом

## 4. Конфигуратор — техническая спецификация

### 4.1 Внешний вид

Каждая услуга — строка:
- Индикатор категории (цветной тег: БАЗА / РЕКОМЕНДОВАНО / ОПЦИОНАЛЬНО / СЛЕДУЮЩИЙ ЭТАП)
- Название услуги
- Цена
- Чекбокс (или замок / иконка для заблокированных)
- Для СЛЕДУЮЩЕГО ЭТАПА — пояснение почему не сейчас

Итого — пересчитывается в реальном времени при каждом клике.

Поле телефона/email + кнопка «Получить расчёт и уточнить детали».

### 4.2 Данные

```python
class ServiceItem:
    id: str
    name: str
    category: Literal["base", "recommended", "optional", "next_stage"]
    price: int  # рублей/мес
    price_note: str | None  # "единоразово" для аудита
    deferred_reason: str | None  # пояснение для next_stage
    selected: bool  # начальное состояние
    locked: bool    # нельзя изменить
```

### 4.3 Интенсивность — наша экспертиза

Конфигуратор бинарный (берём/не берём). Интенсивность (2-3 статьи/нед, количество постов, частота) — наша рекомендация, обоснованная:
- Поисковики видят нейрослоп при высокой частоте
- Плавный рост = выше LTV
- Равномерная загрузка производства

### 4.4 Категоризация — автоматическая

Категории назначаются правилами на основе данных prescan. Не руками.

Правила живут в `AIM/hermes/knowledge/proposals/categorization_rules.md` или в коде как `ServiceCategorizer`.

## 5. Интеграция в КП (11 блоков)

| Блок | Содержание | Изменения |
|---|---|---|
| 0 | Executive Summary | Без изменений |
| 1 | Конкуренты | Без изменений |
| 2 | Cost of Inaction | Без изменений |
| 3 | Проблема | Без изменений |
| 4 | Решение + Success | Без изменений |
| **5** | **Обоснование услуг** | **Меняется:** нарратив про ПОЧЕМУ эти услуги (без таблиц) |
| 6 | Дорожная карта | milestone'ы: СЛЕДУЮЩИЙ ЭТАП → фаза 2 |
| 7 | Альтернативы | Без изменений |
| 8 | Риски | Без изменений |
| 9 | Юр.чистота | Без изменений |
| **10** | **Конфигуратор** | **Меняется:** вместо 3-уровневой цены — форма-конструктор. CTA — в чате (шаг 6). |

## 6. Два формата: чат и КП

**Чат Hermes (шаг 6)** — выжимка на минуту:
- 3 пункта что делать, цена, результат
- Ссылка на полный КП
- «Поговорите с Михаилом» для handoff

**HTML-КП** — полный документ для тех, кто хочет разобраться:
- 11 блоков: от Executive Summary до конфигуратора
- Блок 10: форма-конструктор с чекбоксами и расчётом
- Кнопка «Получить расчёт и уточнить детали» → заявка Михаилу
