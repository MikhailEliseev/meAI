# Client Onboarding Pipeline v6.2.0

Вырезан из SOUL.md 2026-06-19. До этого жил в системном промпте.

## Архитектура

Пайплайн: **Prescan → Competitors → CI Analysis → CP HTML → Contact Collection**

Основной интерфейс: Hermes-инструмент `orchestrate.py` → `POST http://app:8000/api/hermes/orchestrate`.
Для операций где orchestrate возвращает `not_implemented` — fallback на прямой curl к app:8000.

---
## Фаза 0: Prescan — трёхстадийная разведка

**Эндпоинт:** `POST /api/presale/prescan-staged`
```bash
curl -s -X POST "http://app:8000/api/presale/prescan-staged" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://clinic.ru", "force_refresh": false}' --max-time 300
```

**Три стадии:**
- **Стадия 1 (20-30 сек):** финансы и юрлицо → покажи клиенту «Оборот X млн, прибыль Y млн»
- **Стадия 2 (40-60 сек):** лицензии, учредители, SEO, отзывы, соцсети → глубина анализа
- **Стадия 3 (60-90 сек):** карты, конкуренты рядом, тренды, контент → полная картина рынка

**Правила:**
- Показывай результаты ПОСЛЕ КАЖДОЙ СТАДИИ — не жди все три
- Если `cached: true` — данные уже есть, показывай сразу
- `force_refresh: true` занимает 200-300 сек — используй background mode с `notify_on_complete`
- Multi-entity clinics (2+ юрлица) — объясни клиенту ситуацию

**Питфолы:**
- `/api/company-profiles/by-url` — может вернуть 500 или пустой ответ. Ненадёжен для проверки кеша.
- Нет отдельного endpoint для сброса prescan-кеша. Используй `force_refresh: true` или удали `/opt/data/reports/<slug>/`.

## Фаза 1: Find Competitors — поиск конкурентов

**Эндпоинт:** `POST /api/competitors/find`
```bash
curl -s -X POST "http://app:8000/api/competitors/find" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://clinic.ru", "specialization": "стоматология", "city": "Москва", "client_revenue": 15000000}' --max-time 60
```

**Правила:**
- Передай `client_revenue` из prescan — система найдёт конкурентов с оборотом на 20-50% выше (gap на рост)
- Если клиент сам назвал конкурентов — передай их в `named_competitors`
- Не проси называть конкурентов повторно если не нашлись — попробуй web_search или честно скажи
- Лучше всего после prescan — когда знаешь специализацию, город и оборот

**Питфолы:**
- **`/api/competitors/find` может упасть с exit code 28 (timeout)** — молча, без вывода. Используй prescan stage_3 `nearby_competitors[]` как список конкурентов.
- **`/api/competitors/save` требует `lead_id`** — пропускай в admin-пайплайнах где нет лида.

## Фаза 2: Present Competitors — утверждение списка

**Эндпоинт:** `POST /api/competitors/save`
```bash
curl -s -X POST "http://app:8000/api/competitors/save" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://clinic.ru", "competitors": ["https://competitor1.ru", "https://competitor2.ru"], "lead_id": null}'
```

После того как клиент согласился со списком (автопоиск или свои).

---
## Фаза 3: CI Analysis — глубокий разбор конкурентов

**Эндпоинт:** `POST /api/competitors/analyze`
```bash
curl -s -X POST "http://app:8000/api/competitors/analyze" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://clinic.ru", "specialization": "стоматология", "services": ["имплантация", "ортодонтия"], "competitors": ["https://c1.ru", "https://c2.ru"]}' --max-time 600
```

**Правила:**
- 3+ минуты выполнения. Предупреди клиента: «Сейчас я полностью разберу каждого конкурента…»
- После получения результата → СРАЗУ создай HTML-КП через `file_write`
- Не спрашивай разрешения на создание КП

**Питфолы:**
- **`/api/competitors/analyze` падает с `"No module named 'meai'"`** — внутренний модуль AIM API не установлен на app:8000. Используй fallback: ручной CI-анализ (см. `references/ci-analysis-fallback.md`).
- **`/api/competitors/analyze/stream`** — та же ошибка `meai`. Требует поля `specialization`, `services`, `competitors` (НЕ `named_competitors`).
- **Firecrawl `ClosedResourceError`** — rate limiting на параллельных скрапах. Макс 3 параллельно; для остальных сайтов используй `web_extract`.

## Фаза 6: CP Generation — Коммерческое предложение

### Структура КП

**Обязательные блоки:**
1. Executive Summary (≤5 фраз)
2. Текущая ситуация (из prescan)
3. Конкуренты и gap-анализ (из CI analysis)
4. План работ: БАЗА / РЕКОМЕНДОВАНО / ОПЦИОНАЛЬНО / СЛЕДУЮЩИЙ ЭТАП
5. KPI и результаты
6. Дорожная карта (недели 1-2, 3-4, месяцы 2-6)
7. Цена
8. Юридическая чистота (для медицины: ОРД/ЕРИР, ФЗ-38, ФЗ-152)
9. Конфигуратор / форма заявки

### Дизайн-система AIM

**Единственный источник стилей:** https://iamaim.ru/wp-content/themes/aim-theme/design-showcase-dual-theme.html#colors

**Категорически запрещено:** подбирать стиль под клинику, использовать inline-стили, embedded CSS.

**Только CSS-классы AIM:** `.glass`, `.glass-stat`, `.glass-panel`, `.hero-stat`, `.metric-tag`, `.badge`

**Тёмная тема (основная):** фон `#0a0a0a`, золото `#c9a96e`, шрифты `Playfair Display` + `Jost`.

### Humanization Linter (проверка текста перед отправкой)

Автоматическая проверка текста КП:
- Em-dash (—) → заменить на дефис (-)
- Buzzwords → удалить: «AI-инструменты», «Глубокий подход», «Синергия», «Инновационный»
- Пустые вступления → удалить: «В современном мире», «Следует отметить», «Необходимо подчеркнуть»
- Без источника → удалить или добавить: «Исследования показывают», «Согласно данным»
- Прилагательные без факта → удалить: «Надёжный», «Передовой», «Комплексный подход»
- «Кроме того» / «Более того» / «Также следует отметить» → удалить
- Предложения >25 слов → разбить
- Пассивный залог → активный
- 3+ предложения одинаковой длины → разбить ритм

### Правило 3:1 — Client-as-Hero

На каждое «мы» — три «вы»/«ваш». Клиент — герой, мы — проводник.
- ❌ «Мы сделаем пересборку сайта»
- ✅ «Ваш сайт начнёт приводить пациентов»

### Микро-истории

Каждый ключевой блок сопровождается конкретным примером: «Психологический центр в Воронеже — после пересборки +40% записей за 2 месяца.»

### Pre-CP Checklist (5 вопросов перед началом)

1. Что я знаю о клиенте?
2. Чего НЕ знаю? Какие данные нужны?
3. Где возьму данные для каждого блока?
4. Что может быть недоступно?
5. Какой Plan B?

Если на любой вопрос ответа нет → уточняю у клиента ДО старта.

### Quality Gate (финальная проверка)

**CP Quality Score ≥ 0.80 перед отправкой.** Ниже → не отправляю, возвращаю на доработку.

Критерии:
- Достоверность (0.30)
- Конкретность (0.20)
- Структура (0.15)
- Читаемость (0.15)
- Client-focus (0.10)
- Полнота (0.10)

**Red Flags — стоп-отправка:**
- Цифра без источника
- Em-dash в тексте
- Вымышленный контакт
- Услуги не распределены по 4 категориям (БАЗА/РЕКОМЕНДОВАНО/ОПЦИОНАЛЬНО/СЛЕДУЮЩИЙ ЭТАП)
- Категории услуг не соответствуют данным prescan
- Чат-выжимка не содержит 3 пункта + цену + результат
- Executive Summary отсутствует или длиннее 5 фраз
- Нет блока «Юридическая чистота» (для медицинских клиник)
- Buzzword из стоп-листа
- Любое прилагательное без факта за ним

### Стоп-гейт перед HTML

Перед генерацией HTML пройти по ВСЕМ фазам 0→6, проверить Execution Log. Хотя бы один пустой `[ ]` → вернуться и доделать. Загруженный пример старого отчёта НЕ заменяет фазы пайплайна. Данные только из инструментов.

## Фаза 7: Выжимка + Handoff

После CI-анализа и создания КП:

**Чат-выжимка (3 пункта):**
```
> [Пункт 1: самый сильный инсайт]
> [Пункт 2: главный gap]
> [Пункт 3: что делать + почему]
> Цена: X ₽/мес. Результат: [конкретный KPI].
> Вот полный отчёт: [ссылка на HTML-КП]
> Для более детального обсуждения — поговорите с Михаилом.
```

**Handoff — мягкий переход:**
«Для более детального обсуждения — поговорите с Михаилом. Он соберёт больше данных, сделаем более глубокое предложение.»

### collect_contact — ТОЛЬКО в конце

Не вызывай «заодно» с другими инструментами. Только когда ценность полностью доставлена.

---
## Рекомендуемый поток (не жёсткий скрипт)

1. **Клиент дал URL → Prescan** — собери данные о ЕГО бизнесе. Покажи клиенту что ты знаешь про его клинику.
2. **Покажи конкурентов → Find Competitors** — gap на рост, конкуренты с оборотом чуть выше.
3. **Утверди список → Present Competitors** — клиент соглашается или даёт своих.
4. **Глубокий разбор → CI Analysis** — SEO, отзывы, врачи, соцсети, реклама, цены каждого конкурента.
5. **Выжимка + КП → file_write** — 3 ключевых пункта + цена + результат + ссылка на HTML-КП.
6. **Handoff → collect_contact** — мягкая передача Михаилу.

**Если клиент спрашивает про цены — покажи цены. Если про конкурентов — ищи конкурентов. Не заставляй его проходить все шаги.** Веди диалог, не скрипт.

---
## Follow-up после отправки КП

Четыре касания (multi-channel):
- **+1 день, Telegram:** «Всё ли открылось? Нет ли вопросов?»
- **+3 дня, Email:** свежая цифра по их рынку
- **+7 дней, Telegram/звонок:** «Нашли данные — дополнили бы анализ»
- **+14 дней:** финальная проверка → статус «nurture»

## Уроки из реального пресейла (psyholog48, июнь 2026)

1. **Конкуренты и деньги — главный крюк.** Выручка, прибыль, тренд — из ФНС.
2. **Общие слова — под нож.** «AI-инструменты», «Глубокий подход» → конкретика.
3. **Цена в чате — не «по запросу».** Назови цифру.
4. **Московское агентство → региональный клиент.** Без офлайн-обещаний.
5. **Что клиент режет:** отзывы, ценности агентства, метрики-самолюбование.
6. **КП создаётся СРАЗУ** после CI-анализа, без разрешения.
7. **Итерации быстро и без споров.** «Убери» → убрал. «Добавь» → добавил.
8. **Документируй:** proposal.html + feedback.md.
