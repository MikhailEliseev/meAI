### Что сработало
- shell_exec-диагностика быстро выявила корень проблемы: в /etc/resolv.conf отсутствовал Docker DNS (127.0.0.11), контейнер использовал только внешние DNS (8.8.8.8, 1.1.1.1) и не мог резолвить внутреннее имя `app` (сервис AIM API на порту 8000).
- file_read для чтения /etc/resolv.conf подтвердил отсутствие нужного nameserver.

### Что не сработало
- show_all_leads и orchestrate lead_management упали с «Cannot reach AIM API» — все инструменты, завязанные на внутренний Docker-сервис `app`, были неработоспособны без Docker DNS.
- Три попытки orchestrate провалились прежде чем началась диагностика DNS — следовало раньше заподозрить сетевую проблему, а не повторять упавший инструмент.

### На будущее
- Если инструмент падает с «Cannot reach» / «Connection refused» к внутреннему хосту — сразу проверять DNS (cat /etc/resolv.conf, nslookup/ping) ПЕРЕД тем как повторять инструмент.
- При развёртывании в Docker: убедиться что 127.0.0.11 есть в resolv.conf контейнера, иначе внутренние сервисы недоступны.
