# Development Checkpoints System

## Быстрый старт

**При потере контекста или начале новой сессии:**

```bash
# 1. Прочитай последний чекпоинт
cat CHECKPOINTS.md | grep -A 50 "## Checkpoint #"

# 2. Посмотри текущее состояние
cat CHECKPOINTS.md | grep -A 30 "## Current State"

# 3. Проверь приоритеты
cat CHECKPOINTS.md | grep -A 10 "Следующие приоритеты"
```

## Структура чекпоинта

Каждый чекпоинт содержит:

- **Что сделано** - список завершённых задач (с ✅)
- **Ключевые файлы** - важные файлы для проверки
- **Ключевые концепции** - важные идеи и решения
- **Контекст для продолжения** - что нужно знать для следующего шага
- **Следующий шаг** - что делать дальше

## Когда создавать чекпоинт

Создавай новый чекпоинт когда:

1. ✅ Завершена крупная фаза работы (новый агент, система, интеграция)
2. ✅ Реализован новый компонент с кодом
3. ✅ Изменена архитектура системы
4. ✅ Создана новая документация (>5 файлов)
5. ✅ Сессия длится >2 часа

**НЕ создавай чекпоинт для:**
- Мелких багфиксов
- Обновления документации
- Рефакторинга без изменения логики

## Как создать чекпоинт

1. Открой `CHECKPOINTS.md`
2. Скопируй шаблон последнего чекпоинта
3. Увеличь номер (Checkpoint #6, #7, etc.)
4. Заполни все секции
5. Обнови "Current State"
6. Закоммить в git

## Ключевые концепции (всегда актуальны)

Эти концепции НЕ меняются между чекпоинтами:

1. **LLM Wiki Pattern** - ЗАКОН для всех vaults
2. **Иерархия** - YOU → Architect → Operator → Teacher → Magisters → Subagents
3. **Event-driven** - вся коммуникация через Event Bus
4. **Feedback Loop** - обратная связь для улучшения
5. **Continuous Improvement** - система сама себя улучшает
