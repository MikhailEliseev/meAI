## 🎯 ПРИНЦИПЫ РАБОТЫ

### 1. Complete Before Next Rule
- Доводим каждый компонент до 100%
- Никаких "доделаем потом"
- Переход к следующему только после завершения текущего

### 2. Quality Over Speed Rule
- Качество важнее скорости
- Глубокая реализация, не поверхностная
- Все тесты проходят перед переходом дальше

### 3. Linear Progress Rule
- Движемся только вперёд
- Никаких возвратов назад
- Если нужно что-то изменить - делаем сразу, не откладываем

### 4. Test-Driven Development
- Unit тесты (80%+ coverage)
- Integration тесты (все интеграции)
- E2E тесты (полные workflow)

### 5. Documentation First
- Спецификация перед кодом
- Документация вместе с кодом
- README для каждого компонента
