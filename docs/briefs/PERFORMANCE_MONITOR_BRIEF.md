# Бриф: Performance Monitor Agent

**Дата:** 2026-05-11  
**Приоритет:** P1  
**Родительский Magister:** Ads Magister

## Назначение

Мониторинг производительности рекламных кампаний с итеративным подходом (не real-time 24/7, а оптимальная частота проверок). Детекция аномалий и алертинг при отклонениях >20%.

## Контекст и специфика

**Метрики для отслеживания:**
- CTR (Click-Through Rate)
- CPC (Cost Per Click)
- CPA (Cost Per Acquisition)
- Конверсии
- ROI (Return on Investment)
- Quality Score

**Аномалия-детекция:**
- Резкие падения CTR
- Рост CPA
- Падение конверсий
- Другие значимые отклонения (>20% от baseline)

**Пороги для алертов:**
- 20% отклонение от baseline → алерт

**Медицинская специфика:**
- Сезонные паттерны (грипп зимой, аллергии весной, косметология перед летом)
- LTV оптимизация (пациенты возвращаются)
- Geo-специфичное бюджетирование (разные регионы = разная стоимость)

**Итеративный подход:**
- Не постоянный мониторинг 24/7
- Оптимальная частота проверок (балансировка ресурсов и актуальности)

## Интеграции

**Входные данные:**
- API платформ напрямую (чище процесс, без посредников)
- Яндекс.Директ API (P0)
- VK Ads API (P1)
- myTarget API (P2)
- Telegram Ads API (P2)
- Дзен API (P2)

**Выходные данные:**
- Алерты для Budget Optimizer Agent (при аномалиях)
- Метрики для Analytics Agent (агрегация и анализ)
- Уведомления в Telegram (критичные алерты)

**Связанные агенты:**
- Budget Optimizer Agent — получатель алертов об аномалиях
- Analytics Agent — получатель метрик для агрегации
- Campaign Manager Agent — источник контекста кампаний (опционально)

**Внешние API:**
- Яндекс.Директ API (P0) — сбор метрик кампаний
- VK Ads API (P1) — сбор метрик кампаний

- Telegram Ads API (P2) — сбор метрик кампаний
- Дзен API (P2) — сбор метрик кампаний

## Приоритеты исследования

### 🔴 КРИТИЧНО (обязательно глубоко изучить)

1. **Metrics collection strategies**
   - Оптимальная частота сбора данных (балансировка ресурсов и актуальности)
   - Батчинг запросов к API (эффективность)
   - API rate limits и квоты (ограничения платформ)
   - Стратегии обработки ошибок API
   - Кэширование и дедупликация данных

2. **Anomaly detection algorithms**
   - Статистические методы детекции аномалий
   - Baseline calculation (как вычислять нормальное поведение)
   - Threshold-based detection (пороговые значения)
   - Time-series analysis (анализ временных рядов)
   - Сезонная корректировка (учёт медицинской специфики)

### 🟡 ВАЖНО (изучить, но не так глубоко)

1. **Multi-platform monitoring**
   - Особенности API разных платформ
   - Различия в метриках и их названиях
   - Rate limits и квоты по платформам
   - Унификация данных из разных источников

2. **Medical marketing KPIs**
   - Специфичные метрики для медицинского маркетинга
   - Сезонные паттерны и их влияние на метрики
   - LTV-ориентированные метрики
   - Geo-специфичные KPI

3. **Real-time vs batch processing**
   - Оптимальная частота проверок
   - Балансировка между актуальностью и ресурсами
   - Когда нужен real-time, когда достаточно batch

### 🟢 ОПЦИОНАЛЬНО (можно пропустить или поверхностно)

1. **Alert thresholds and rules**
   - Когда и как алертить (простой подход: аномалия → алерт)
   - Приоритизация алертов
   - Escalation rules

2. **Machine learning for anomaly detection**
   - ML модели для детекции (можно начать с простых статистических методов)
   - Обучение на исторических данных
   - Автоматическая адаптация baseline

3. **Predictive analytics**
   - Прогнозирование метрик
   - Early warning системы
   - Trend analysis
