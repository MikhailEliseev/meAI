# Spec Writer v2.0 — Гибридный подход

**Цель:** Создавать максимально точные спецификации агентов через трёхэтапный процесс: бриф от пользователя → целевое исследование → написание спецификации.

**Принцип работы:**
1. **Этап 1: Бриф** — получить от пользователя вводные данные об агенте
2. **Этап 2: Целевое исследование** — на основе брифа сформировать точный запрос для deep-research
3. **Этап 3: Написание** — создать спецификацию на основе исследования
4. **Этап 4: Архивирование** — сохранить исследование в vault для переиспользования

---

## Когда использовать

Используй этот skill когда:
- Нужно создать спецификацию нового агента/субагента
- Пользователь готов дать вводные данные об агенте
- Требуется глубокое понимание предметной области
- Нужно избежать упущений в спецификации

**НЕ используй** когда:
- Спецификация уже существует (используй для доработки)
- Пользователь не может дать вводные (тогда используй старый подход)
- Нужно просто обновить существующую спецификацию

## Workflow

### Этап 1: Бриф от пользователя (5-10 минут)

**Цель:** Получить максимум контекста от пользователя для точного исследования.

**Запроси у пользователя (текстом или через вопросы):**

1. **Название и назначение:**
   - Как называется агент?
   - Какую основную задачу он решает?
   - Какой Magister является родительским?

2. **Контекст и специфика:**
   - Какие особенности предметной области важны?
   - Есть ли специфические требования (медицинская специфика, compliance, etc.)?
   - Какие проблемы агент должен решать?

3. **Интеграции и зависимости:**
   - С какими другими агентами взаимодействует?
   - Какие внешние API/сервисы использует?
   - Какие данные получает на вход и что возвращает?

4. **Приоритеты исследования:**
   - Что КРИТИЧНО изучить для этого агента?
   - Что ВАЖНО, но не критично?
   - Что можно пропустить или изучить поверхностно?

**Сохрани бриф в `docs/briefs/[AGENT_NAME]_BRIEF.md`:**

```markdown
# Бриф: [Agent Name]

**Дата:** YYYY-MM-DD  
**Приоритет:** P0/P1/P2  
**Родительский Magister:** [Name]

## Назначение

[Основная задача агента]

## Контекст и специфика

[Особенности предметной области, требования, проблемы]

## Интеграции

**Входные данные:**
- [Что получает]

**Выходные данные:**
- [Что возвращает]

**Связанные агенты:**
- [Список агентов]

**Внешние API:**
- [Список API/сервисов]

## Приоритеты исследования

### 🔴 КРИТИЧНО (обязательно глубоко изучить)
- [Пункт 1]
- [Пункт 2]

### 🟡 ВАЖНО (изучить, но не так глубоко)
- [Пункт 1]
- [Пункт 2]

### 🟢 ОПЦИОНАЛЬНО (можно пропустить или поверхностно)
- [Пункт 1]
- [Пункт 2]

## Дополнительные материалы

**Интервью:** [Ссылка на интервью, если есть]  
**Связанные спецификации:** [Список]  
**TODO из других агентов:** [Список]
```

### Этап 2: Целевое исследование (10-20 минут)

#### 2.1 Проверка vault на переиспользование

**Перед исследованием проверь `obsidian/deep-research/wiki/topics/`:**

```bash
grep -r "[ключевые слова из брифа]" obsidian/deep-research/wiki/topics/
```

**Если нашёл похожее исследование (>70% совпадение):**
- Прочитай его
- Используй существующее исследование
- Пропусти deep-research
- Обнови `manifest.json`: добавь агента в `reused_by`

#### 2.2 Формирование запроса для deep-research

**На основе брифа создай детальный запрос:**

```
[Название агента]: [Основная задача из брифа]

КРИТИЧНО изучить (глубоко):
1. [Критичный аспект 1 из брифа]
2. [Критичный аспект 2 из брифа]
3. [Критичный аспект 3 из брифа]

ВАЖНО изучить (средняя глубина):
1. [Важный аспект 1 из брифа]
2. [Важный аспект 2 из брифа]

ОПЦИОНАЛЬНО (поверхностно или пропустить):
1. [Опциональный аспект 1 из брифа]

СПЕЦИФИКА:
- [Особенности из брифа: медицинская специфика, compliance, etc.]

ИНТЕГРАЦИИ:
- [API и сервисы из брифа]

МЕТРИКИ:
- [Что измерять для успеха агента]
```

#### 2.3 Выбор режима исследования

**Критерии выбора:**
- **deep** (8 фаз, 10-20 минут):
  - >3 критичных аспектов в брифе
  - Медицинская/финансовая/юридическая специфика
  - Сложная предметная область
  
- **standard** (6 фаз, 5-10 минут):
  - ≤3 критичных аспектов
  - Типовая задача без специфики
  - Похожие агенты уже исследованы

#### 2.4 Запуск deep-research

```
/deep-research [сформированный запрос]
```

### Этап 3: Анализ исследования (5-10 минут)

#### 3.1 Чтение отчёта

**Найди отчёт:**
```bash
ls -la ~/Documents/ | grep Research | tail -1
```

**Основной файл:** `[Topic]_Research_Report.md`

#### 3.2 Mapping: исследование → спецификация

| Раздел исследования | Раздел спецификации | Что извлечь |
|---------------------|---------------------|-------------|
| Executive Summary | Раздел 1 (Обзор) | Уникальная ценность, статистика |
| Data Requirements | Раздел 2 (Входные данные) | Параметры |
| Best Practices | Раздел 3 (Алгоритм работы) | Шаги, код |
| Success Metrics | Раздел 5 (Метрики успеха) | KPI, бенчмарки |
| Common Pitfalls | Раздел 7 (Обработка ошибок) | Ошибки, решения |
| Implementation Examples | Раздел 9 (Примеры) | Сценарии, код |
| Tools & APIs | Раздел 10 (Зависимости) | API, цены |
| Future Research | Приложение A (TODO) | Что изучить |

#### 3.3 Проверка полноты

**Чеклист:**
- ✅ Статистика с источниками?
- ✅ API с ценами и лимитами?
- ✅ Метрики и бенчмарки?
- ✅ Лучшие практики с кодом?
- ✅ Типичные ошибки и решения?

### Этап 4: Создание спецификации (30-40 минут)

**Используй шаблон:** `docs/templates/SUBAGENT_SPEC_TEMPLATE.md`  
**Используй паттерны:** `docs/ARCHITECTURE-COMMUNICATION.md`

**Источники данных для секций:**

- **Секция 1 (Обзор):** Бриф (назначение, роль) + Исследование (статистика)
- **Секция 2 (Входные данные):** Бриф + Исследование (Data Requirements)
- **Секция 3 (Алгоритм):** Исследование (Best Practices) + Бриф (специфика)
- **Секция 4 (Выходные данные):** Бриф + Паттерны (Event Bus)
- **Секция 5 (Метрики):** Исследование (Success Metrics) + Бриф (приоритеты)
- **Секция 6 (Коммуникация):** Паттерны (стандартные) + Бриф (агенты)
- **Секция 7 (Ошибки):** Исследование (Common Pitfalls) + Паттерны (retry)
- **Секция 8 (Тестирование):** Паттерны (стандартные) + Бриф (критичные аспекты)
- **Секция 9 (Примеры):** Исследование (Implementation Examples) + Бриф (интеграции)
- **Секция 10 (Зависимости):** Исследование (Tools & APIs) + Бриф (внешние API)
- **Секция 11 (Deployment):** Паттерны (Docker) + Бриф (специфика)
- **Секция 12 (Changelog):** Дата + summary из брифа
- **Секция 13 (TODO):** Исследование (Future Research) + Бриф (опциональное)
- **Приложение A:** Весь отчёт исследования

**Проверка качества:**
- ✅ Размер > 30 KB
- ✅ Все секции заполнены
- ✅ Примеры кода рабочие
- ✅ Статистика с источниками
- ✅ API с ценами
- ✅ Метрики определены

---

### Этап 5: Архивирование исследования (5 минут)

```bash
python scripts/ingest_research.py ~/Documents/[Topic]_Research_[YYYYMMDD]/
```

**Проверь:**
- ✅ Исследование в `obsidian/deep-research/raw/`
- ✅ Запись в `wiki/log.md`
- ✅ Статистика обновлена в `wiki/statistics/usage.md`
