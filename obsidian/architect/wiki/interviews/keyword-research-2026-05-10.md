## Финальное определение

**Keyword Research Agent = Подборщик ключевых слов для роста трафика**

- Подключается к Яндекс Вордстат, Google Keyword Planner, Метрике, Analytics
- Собирает статистику по ключевым словам (частотность, конкуренция, сезонность)
- Отслеживает позиции сайта в поисковых системах
- Показывает видимость сайта и зависимость трафика от ключевых слов
- Даёт рекомендации по использованию ключевых слов (Title, Description, H1)

## Блок 1: Роль и уникальность

**Q1: Что делает Keyword Research Agent?**

A: Подбор ключевых слов для роста трафика конкретного сайта. Подключается к Яндекс Вордстат, собирает статистику по ключевым словам, отслеживает позиции сайта в поисковых системах. Показывает видимость сайта в поиске и зависимость трафика от ключевых слов. Помогает понять, по каким ключевым словам сайт уже получает трафик и какие новые ключевые слова добавить для роста.

**Q2: Почему это критично для системы?**

A: SEO — один из основных каналов привлечения платежеспособного трафика из поиска. Без подбора ключевых слов невозможно построить SEO стратегию и расти в органической выдаче. Это фундамент всей SEO работы.

**Важное уточнение:** В пару к Keyword Research Agent нужен **GEO Agent** (Generative Engine Optimization) — узконаправленный агент для оптимизации под нейросети (ChatGPT, Perplexity, Claude). Это отдельный P1 агент, добавляем в список.

**Q3: Что агент НЕ делает?**

A: 
- ❌ Не пишет тексты для оптимизации (это делает Content Agent)
- ❌ Не оптимизирует существующий контент (это другие агенты)
- ✅ Только подбирает ключевые слова и даёт рекомендации по их использованию для контента

## Блок 2: Входные данные и источники

**Q4: Какие данные нужны агенту для работы?**

A:

**Обязательные источники:**
- **Яндекс Вордстат** — статистика запросов Яндекса (частотность, сезонность)
- **Google Keyword Planner** — статистика запросов Google (если есть API)
- **Яндекс Метрика** — по каким ключевым словам уже заходят на сайт (реальный трафик)
- **Google Analytics** — по каким ключевым словам уже заходят на сайт
- **Сбор позиций** — текущие позиции сайта в поисковых системах по ключевым словам

**Обязательные параметры:**
- `site_url: str` — URL сайта для анализа
- `project_id: str` — ID проекта (для изоляции данных)
- `yandex_metrika_token: str` — токен Яндекс Метрики
- `google_analytics_token: str` — токен Google Analytics

**Опциональные:**
- `competitors: list[str]` — список конкурентов для сравнения
- `target_region: str` — целевой регион (Москва, Россия, etc.)

**Q5: Есть ли специфичные требования к входным данным?**

A: Специфичных требований нет. Стандартная валидация (URL, токены API).

## Блок 3: Алгоритм и логика

**Q6: Какие основные шаги выполняет агент?**

A: 

1. **Сбор данных из источников** (Яндекс Вордстат, Google Keyword Planner, Метрика, Analytics)
2. **Анализ ключевых слов по параметрам:**
   - Спрос (частотность запросов)
   - Точное вхождение vs неточное вхождение
   - Сезонность
   - Конкуренция
3. **Анализ текущих позиций** — как сайт находится в поиске по этим ключевым словам
4. **Генерация рекомендаций:**
   - Какие ключевые слова добавить в контент
   - Куда включить (Title, Description, Keywords, H1, текст)
   - Приоритизация по потенциалу трафика
5. **Сохранение результатов** — список ключевых слов с метриками и рекомендациями

**Q7: Есть ли специфичная логика обработки?**

A: Специфичных алгоритмов и формул нет. Стандартная обработка: fetch → process → save.

## Блок 4: Результаты и метрики

**Q9: Что агент возвращает в результате?**

A: 

**Результат (структура определяется архитектурой):**
- Список ключевых слов с метриками:
  - Ключевое слово
  - Частотность (Яндекс + Google)
  - Текущая позиция сайта

- Группировка ключевых слов по темам/страницам

**Куда сохраняется:**
- База данных (структурированные метрики)
- Obsidian vault (история, инсайты, рекомендации)

## Блок 5: Особенности и edge cases

**Q11: Есть ли специфичные ошибки или edge cases?**

A: Специфичных ошибок нет. Стандартные:
- API_UNAVAILABLE (Яндекс Вордстат, Google, Метрика недоступны)
- TIMEOUT (долгий сбор данных)
- INVALID_INPUT (неверный URL сайта, токены)
- RATE_LIMIT_EXCEEDED (превышен лимит запросов к API)

**Q12: Есть ли особенности интеграции с Magister?**

A: Стандартный подход через Event Bus:
- Получает задачи от SEO Magister через `seo.keyword_research.requested`
- Отправляет результаты через `seo.keyword_research.completed`
- Correlation ID для трейсинга
- Логирование в Event Store

Специальных требований к координации нет.
