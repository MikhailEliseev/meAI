# Strategic Decision: Zero Hallucinations System

## Question

Как гарантировать, что CI система не выдумывает данные и работает только с проверенными фактами из внешних источников?

## Decision

**Внедрить Data Provenance System** - систему отслеживания происхождения каждого факта с явным разделением "есть данные" vs "нет данных".

## Rationale

### Почему это лучший выбор:

1. **Прослеживаемость** - каждый факт имеет источник (API, scraping, manual input)
2. **Явность** - система явно говорит "нет данных" вместо выдумывания
3. **Доверие** - клиенты видят источники данных в отчётах
4. **Аудит** - полная история откуда что взялось
5. **Human-in-the-loop** - явные точки для вмешательства человека

### Учёт прошлого опыта:

- У нас уже есть **FactChecker agent** - он проверяет противоречия
- Можно расширить его для проверки источников
- Obsidian vaults уже хранят `raw/` (источники) отдельно от `wiki/` (обработка)

### План отката:

Если система слишком строгая:
1. Добавить `strict_mode: false` флаг
2. В нестрогом режиме - warnings вместо errors
3. Постепенно улучшать покрытие API
4. Включить strict mode когда покрытие > 80%

## Confidence

92% (0.92)

Высокая уверенность, потому что:
- Паттерн проверен в других системах
- У нас уже есть базовая инфраструктура (FactChecker, Obsidian)
- Риски управляемы

Не 95%+, потому что:
- Нужно протестировать на реальных данных
- Может потребоваться доработка API интеграций

## Alternatives Considered

### 1. Strict Validation Rules (жёсткие правила)

**Плюсы:**
- Проще реализовать
- Быстрее работает
- Меньше кода

**Минусы:**
- Менее гибко
- Не показывает источник данных
- Сложно отлаживать

**Почему не выбрали:** Не решает проблему прослеживаемости

### 2. Manual Review Gates (ручная проверка)

**Плюсы:**
- 100% надёжность
- Человек видит все данные
- Нет риска галлюцинаций

**Минусы:**
- Очень медленно (часы вместо минут)
- Не масштабируется
- Дорого (нужен человек)

**Почему не выбрали:** Убивает автоматизацию

### 3. Ничего не делать

**Плюсы:**
- Не нужно ничего делать
- Система работает как есть

**Минусы:**
- Риск галлюцинаций остаётся
- Потеря доверия клиентов
- Ошибочные решения

**Почему не выбрали:** Неприемлемый риск для бизнеса

## Risks

### Риск 1: Слишком часто "нет данных"

**Вероятность:** Средняя  
**Влияние:** Среднее (система менее полезна)

**Митигация:**
- Приоритизировать интеграцию API (2GIS, HH, Yandex)
- Добавить web scraping для публичных данных
- Создать UI для ручного ввода недостающих данных
- Показывать % покрытия данных в отчётах

### Риск 2: Увеличение сложности кода

**Вероятность:** Высокая  
**Влияние:** Низкое (больше кода, но структурированно)

**Митигация:**
- Создать базовые классы `VerifiedData`, `DataSource`
- Все агенты наследуют provenance из коробки
- Документация и примеры использования
- Code review на соблюдение паттерна

### Риск 3: Замедление работы

**Вероятность:** Низкая  
**Влияние:** Низкое (несколько секунд)

**Митигация:**
- Кэширование проверенных данных
- Асинхронная валидация
- Batch проверка источников
- Оптимизация запросов к БД

## Implementation Plan

### Phase 1: Data Provenance Framework (2-3 дня)

**Задачи:**
1. Создать `src/meai/data/provenance.py`:
   - `DataSource` - источник данных (API, scraping, manual)
   - `VerifiedData` - данные с источником
   - `ProvenanceTracker` - отслеживание цепочки
2. Создать `src/meai/data/validation.py`:
   - `DataValidator` - проверка наличия источника
   - `MissingDataError` - явная ошибка "нет данных"
   - `DataQualityScore` - оценка качества источника
3. Обновить `base_agent.py`:
   - Добавить `verify_data()` метод
   - Добавить `report_missing_data()` метод
   - Логирование источников в Obsidian

### Phase 2: Update CI Agents (3-4 дня)

**Задачи:**
1. Обновить все 16 CI агентов:
   - Оборачивать все данные в `VerifiedData`
   - Указывать источник для каждого факта
   - Явно обрабатывать `MissingDataError`
2. Обновить HH Agent:
   - Добавить `source="hh_api"` для всех данных
   - Логировать API calls
3. Обновить FactChecker:
   - Проверять наличие источников
   - Флагировать данные без источников
   - Scoring по качеству источника

### Phase 3: Validation Layer (2 дня)

**Задачи:**
1. Создать `src/meai/data/validation_layer.py`:
   - Проверка перед сохранением в JSON
   - Проверка перед передачей Magisters
   - Генерация отчёта о покрытии данных
2. Интеграция с CI Orchestrator:
   - Валидация после каждой фазы
   - Остановка pipeline при критических пробелах
   - Уведомление пользователя о недостающих данных

### Phase 4: Human Review Interface (3-4 дня)

**Задачи:**
1. Создать CLI команду `aim review-missing-data`:
   - Показать список недостающих данных
   - Предложить источники для сбора
   - Ручной ввод данных с указанием источника
2. Создать `AIM/data/manual-inputs.json`:
   - Хранение ручных вводов
   - Timestamp и автор
   - Причина ручного ввода
3. Интеграция с Obsidian:
   - Страница `wiki/missing-data.md` для каждого агента
   - Автоматическое обновление при появлении данных

### Phase 5: Magisters Integration Update (2 дня)

**Задачи:**
1. Обновить `ci_magisters_integration.py`:
   - Использовать только `VerifiedData`
   - Фильтровать данные без источников
   - Добавить `data_coverage` в инсайты
2. Обновить Magisters with CI:
   - Показывать % покрытия данных в планах
   - Явно указывать "нет данных для X"
   - Предлагать альтернативы при пробелах

### Phase 6: Testing & Documentation (2-3 дня)

**Задачи:**
1. Написать тесты:
   - Unit тесты для provenance framework
   - Integration тесты для CI pipeline
   - E2E тест с реальными API
2. Документация:
   - `DATA_PROVENANCE.md` - как работает система
   - `API_INTEGRATION_GUIDE.md` - как добавлять новые API
   - `MISSING_DATA_HANDLING.md` - что делать при пробелах
3. Обучение:
   - Примеры использования для каждого агента
   - Best practices для новых агентов

## Success Metrics

**Как измерить успех:**

1. **Data Coverage** - % данных с источниками > 95%
2. **Zero Hallucinations** - 0 случаев выдуманных данных за месяц
3. **Transparency** - каждый инсайт имеет источник в отчёте
4. **User Trust** - клиенты доверяют данным (опрос)
5. **Audit Trail** - можно проследить любой факт до источника

**Критерии провала:**

- Data coverage < 70% через месяц
- Система слишком медленная (> 2x текущего времени)
- Пользователи жалуются на "слишком много нет данных"
