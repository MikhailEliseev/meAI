## V2 Competitor Pipeline (зафиксировано 2026-07-15, обновлено после аудита)

### Что изменилось
Заменён Google Maps как единственный источник подбора конкурентов на гибридный пайплайн: **Perplexity + SearXNG → bo.nalog → ФНС**. Найдены реальные бизнес-конкуренты по масштабу, а не соседи по карте.

### Архитектура (5 этапов, ~20с)
```
КЛИЕНТ (URL)
  ↓ Этап 0: extract_client_profile + _resolve_client_inn (Perplexity→ФНС)
  ↓ Этап 1: Perplexity (12 брендов, retry 3×) + SearXNG (рейтинги) параллельно
  ↓ Этап 2: brand_resolver → normalize_brand_name → bo.nalog (ИНН, ОКВЭД, name similarity)
  ↓ Этап 3: ФНС финансы + коридор 0.1×–10× + confident-resolve dedup
  ↓ Этап 3.5a: if <count → ОКВЭД-реестр backfill (top по выручке в коридоре)
  ↓ Этап 3.5b: SearXNG Instagram (handle+подписчики) + Perplexity врачи
  → таблица: Конкурент | Выручка | Тренд | Врачи | Instagram
```

### Ключевые решения (после аудита)
- **Confident-resolve дедуп**: при конфликте (несколько брендов → один ИНН) оставляем бренд с лучшим совпадением названия. Остальные выкидываем как ошибочный резолв.
- **Name similarity scoring**: brand_resolver скорит по совпадению названия бренда с юрлицом, не по топ-1 выручке. Фиксит «ЛАНЦЕТЪ» → «ДЕЛАЙТ-ЛАНЦЕТЪ».
- **Singleton client**: `get_nalog_client()` — НИКОГДА не закрывать (finally close ломал все последующие запросы).
- **ОКВЭД backfill**: если Perplexity дал <5 → добор из bo.nалог ОКВЭД 86.xx реестра (top по выручке в коридоре).
- **BfoNalogClient СИНХРОННЫЙ** — всегда обёрнут в `asyncio.to_thread()`.


### Ключевые файлы (aim-app)
| Файл | Назначение |
|------|-----------|
| `services/competitor_matcher_v2.py` | Оркестратор (4 этапа) |
| `services/brand_resolver.py` | бренд→ИНН + normalize_brand_name |
| `services/lib/searxng_client.py` | SearXNG meta-search |
| `services/lib/perplexity_client.py` | Perplexity API для aim-app |
| `services/lib/instagram_enricher.py` | IG handle+подписчики через SearXNG сниппеты |
| `api/competitors.py` | strategy dispatch (v1/v2), CompetitorJson |
| `docker-compose.yml` | SearXNG сервис + PERPLEXITY_API_KEY |

### Endpoint
```
POST /api/competitors/find
{"url": "https://...", "count": 5, "strategy": "v2"}
```
`strategy=v1` — откат на Google Maps (старый пайплайн)

### Что решено (vs Google Maps v1)
| Параметр | V1 (Google Maps) | V2 (Perplexity+ФНС) |
|---|---|---|
| Источник | Соседи по карте | Бизнес-конкуренты по масштабу |
| Выручка | 0/5 (нет) | 5/5 (ФНС, точно) |
| ИНН | 0/5 (пустые) | 5/5 |
| ОКВЭД | 0/5 (None) | 5/5 |
| Instagram | 0/5 | 4/5 (SearXNG) |
| Время | 75с | ~15с |

### Ключевые решения
- **Instagram через SearXNG** (не Apify) — 3с, бесплатно, обходит блокировку РФ
- **«Врачи»** (не «хирурги») — обобщение для любой специализации
- **Коридор 0.1×–10×** — широкий, для крупных и мелких клиентов
- **ИНН клиента через Perplexity** → ФНС валидация (site scrape → bo.nalog → Perplexity fallback)
- **Нормализация брендов** — «Медиал на Ленинском» → «Медиал» перед резолвом

### Известные ограничения
- Perplexity недетерминирован — retry 3× помогает, но не гарантирует
- Сельские клиники (не мегаполис) — не тестировались
- SearXNG Instagram: 30-50% пропусков (нет IG-аккаунта или SearXNG не нашёл)
- Врачи: 30% пропусков (Perplexity не дал оценку)
- Бренд ≠ юрлицо: Seline, Олимп из эталона не находятся (Perplexity называет, резолвер не находит ИНН)
- End-to-end через чат не тестировался (только API endpoint)
- BfoNalogClient синхронный — блокирует event loop под высокой нагрузкой

### Тест IPHK (эталон после всех фиксов)
5 конкурентов, 5 уникальных ИНН, 0 дублей, IG 5/5, врачи 4/5, ~20с.
Реальные: Атлас 1.7B, Столица 947M, Frau Klinik 795M, ЕМС 544M.

## Анти-галлюцинационный слой (зафиксировано 2026-07-15)

### Принцип
**Таблицы и факты формирует Python-код (из ФНС/SearXNG). LLM делает только аналитические выводы.** LLM не может галлюцинировать в таблице — она из кода.

### Файлы (hermes-v2)
| Файл | Назначение |
|------|-----------|
| `app/formatters/competitors.py` | Markdown таблица конкурентов из JSON pipeline |
| `app/formatters/profile.py` | Профиль клиники из extract_clinic_profile JSON |
| `app/llm.py` | `_build_formatted_blocks()` — инъекция перед LLM |
| `app/prompts/dialogue.py` | Промпт «только выводы, НЕ повторяй таблицы» |

### Как работает
1. Тулы выполняются → raw JSON результаты
2. `_build_formatted_blocks()` преобразует JSON в Markdown таблицы
3. Таблицы yield как text-delta (пользователь видит их сразу)
4. System instruction: «данные выше — факты, делай только выводы»
5. LLM генерирует 3-5 предложений аналитики после таблиц

### Незакрытые проблемы (для следующей сессии)
1. **Formatted blocks НЕ в истории сессии** — `async_save_message` сохраняет только LLM ответ. Перезагрузка → таблицы исчезают.
2. **Raw JSON в messages** — LLM видит и таблицу, и сырой JSON (с галлюцинациями quick_overview). Нужно фильтровать tool results.
3. **overview.py форматтер** — не реализован, Perplexity отдаёт свободный текст с аналитикой.
4. **LLM выводы** — всё ещё может галлюцинировать после таблицы.
